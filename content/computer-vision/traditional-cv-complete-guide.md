## 引言：为什么在深度学习时代还要聊传统 CV？

老实说，现在打开任何一个 CV 相关的技术论坛，十条帖子里有九条在聊模型架构搭建、调参、Loss 设计、数据增强策略，还有端到端 、多模态。传统计算机视觉——那些基于像素统计、频域变换、几何不变量的"老方法"——似乎已经成了教科书里的历史遗迹。但如果你真的做过工业质检、机器人视觉或者嵌入式部署，就会发现一个很朴素的事实：**传统 CV 从来没有真正离开过**。

深度学习模型训练的**预处理**（图像去噪、透视矫正、ROI 提取）与**后处理**（NMS 本身就是个经典算法、连通域分析、轮廓拟合）都离不开传统 CV。同时，对于那些延迟要求极苛刻、算力极有限、根本跑不起神经网络的边缘设备而言，传统 CV 往往是唯一现实可行的方案。另外，与 CNN 和 Transformer 相比，传统算法**可解释、可调试、零训练成本**——出了问题你能一步步跟踪到底是哪个像素、哪个阈值出的问题，这在深度学习的黑盒世界里是种奢侈。

写这篇文章的目的是把传统计算机视觉这套**CV界的老一辈打法**梳理一遍：从最基础的图像预处理，到几何变换，再到特征提取、分割、检测、跟踪等任务，对每一类算法进行概述、并给出基于 OpenCV 的具体实现方式。同时，本文重点之一是：讨论不同**算法之间的组合**以解决实际场景中的问题，单个算法很少能独立打天下，真正的工程能力往往体现在"组合拳"怎么打，这些操作恰好是深度学习与多模态下的补充和基础夯实。

## 一、传统 CV 的整体流程范式

在展开具体算法之前，有必要先建立一个全局框架。绝大多数传统 CV 任务，不管表面看起来多么五花八门，底层都可以拆解成下面这条流水线的某个子集：

```
采集/输入 → 预处理 → 特征提取 → 结构化理解（分割/检测/匹配）→ 后处理 → 决策输出
```

- **采集/输入**：相机标定、曝光控制、ROI 裁剪、拍摄角调整
- **预处理**：去噪、灰度化、直方图均衡、几何校正
- **特征提取**：边缘、角点、关键点描述子、纹理特征
- **结构化理解**：把"一堆像素"变成"有意义的结构"——轮廓、区域、目标框、匹配对应关系
- **后处理**：非极大值抑制、形态学处理、卡尔曼滤波平滑
- **决策输出**：分类结果、坐标、计数、报警信号

传统的计算机视觉几乎都是这么个流程，当面对一个新任务时可以按流程思考：采集的数据具有什么特点？预处理需要做什么？特征用什么描述最合适？结构化理解是分割问题还是检测问题？虽然直接下个ultralytics ，再让实习生用label-studio数据打标几行命令开始训练，或者在modelscope或者huggingface下载DINO等预训练模型确实简单，但我觉得传统CV任务的思想依然有值得学习的地方，一些方法可以结合起来取得更好的效果。

### 1.1 传统 CV 主要应用领域（速览）

在进入具体算法细节之前，先把传统 CV 最常落地的场景过一遍。你会发现它们大多有共同点：**场景结构化、约束强、对实时性/可解释性/几何精度有硬要求**。

| 应用领域 | 典型任务 | 传统 CV 常用模块（高频组合） | 采用理由 |
|---|---|---|---|
| 工业视觉检测（Industrial Inspection） | 表面缺陷、尺寸测量、AOI、定位引导、条码/二维码定位 | 预处理（去噪/CLAHE）→ 边缘/轮廓 → 形态学/连通域 → 几何拟合/测量 | 结果确定性强、可解释、精度可做到亚像素，且不依赖训练数据<br />在数据量少、场景和任务单一的情况，传统的模式识别即可完成 |
| 医疗影像增强（Medical Imaging） | 去噪、对比度增强、结构分离（如骨/软组织）、病灶粗定位辅助 | NLM/引导滤波 → 频域/多尺度 → SLIC/区域生长 → 形态学后处理 | 临床/合规场景更偏好可追溯流程；<br />医学领域的很多增强任务本质是信号处理问题，不引入噪声的情况下直方图均衡化、区域生长等算法高效且管用 |
| 计算摄影（Computational Photography） | 全景拼接、文档扫描矫正、手机端美颜/抠图等 | 特征匹配+Homography+融合 / 透视矫正+二值化 / 保边滤波 | 端侧算力受限、延迟敏感；传统算子链路稳定、成本低 |
| 自主系统导航与 SLAM（Navigation & SLAM） | 视觉里程计、特征跟踪、位姿估计、双目深度 | FAST/ORB → 光流/匹配 → RANSAC → PnP/双目视差 | 在嵌入式平台上实现实时定位的“经典路线”，鲁棒性依赖几何约束 |

> 上表是“领域视角”的概览；如果你更想从“任务→算法组合”快速查找，建议直接跳到第十六章的完整流水线案例（尤其是第 16.10 节的速查表）。

### 1.2 典型算法 Pipeline（两条“模板化范式”）

第十六章已经给了很多任务级流水线，这里再补两条更偏“范式模板”的 Pipeline：它们不绑定某个具体行业，但在工程里复用率极高。

**范式 A：工业尺寸测量（测量类问题的通用骨架）**

```
灰度化/去噪 → 边缘定位（Canny 等） → 几何拟合（Hough 线/圆、轮廓拟合）
          →（可选）亚像素边缘/角点精修 → 像素尺度距离计算 → 标定参数换算真实尺寸
```

**范式 B：物体识别与定位（“模板在库里”的定位问题）**

```
关键点与描述子（ORB/SIFT 等） → 描述子匹配（BF/FLANN）→ 比值测试/交叉验证等过滤 → RANSAC 剔除外点 
                          → Homography/位姿解算 → 输出目标位置/姿态/ROI
```

这两条模板背后的要点其实是一样的：**传统 CV 更像是在“可建模约束”下做确定性推理**。

## 二、OpenCV 基础：core 模块速查

在进入图像预处理这类"有算法含量"的内容之前，有必要先把 `core` 模块里那些看似朴素、但天天都在用的基础 API 过一遍。这部分内容技术含量不高，但踩坑率不低——很多"算法没问题、结果却不对"的 bug，根源其实就在这些基础操作上没弄清楚。

### 2.1 图像的读取与保存

```python
img = cv2.imread('input.jpg', cv2.IMREAD_COLOR)   # 也可用 IMREAD_GRAYSCALE / IMREAD_UNCHANGED
cv2.imwrite('output.png', img)

# 中文路径在 Windows 上 cv2.imread/imwrite 可能读写失败，稳妥写法：
img = cv2.imdecode(np.fromfile('中文路径.jpg', dtype=np.uint8), cv2.IMREAD_COLOR)
cv2.imencode('.jpg', img)[1].tofile('中文路径.jpg')
```

`cv2.imread` 读取失败时不会抛异常，只会静默返回 `None`——这是新手最容易忽略的一个坑，工程代码里一定要显式检查 `if img is None`。

### 2.2 Mat 与 ndarray：不同语言下的同一形式

C++ 版 OpenCV 里图像的核心容器是 `Mat`，但在 Python 里，`cv2` 的图像对象本质上就是 **NumPy 的 `ndarray`**——这意味着所有 NumPy 的切片、广播、向量化操作都能直接套用在 OpenCV 图像上，不需要额外学一套"OpenCV 专属"的数据操作语法。

```python
print(img.shape)   # (H, W, 3)，注意是"高在前、宽在后"，和常规 (x, y) 直觉相反
print(img.dtype)   # 通常是 uint8 (0-255)
```

理解"Mat 就是 ndarray"这件事，能省下大量走弯路的时间——很多关于图像的数值运算、条件筛选，直接用 NumPy 语法写就行，不需要现学 OpenCV 的等价 API。

### 2.3 ROI 与通道操作

```python
# ROI 裁剪，本质就是 NumPy 切片（注意，这里修改roi后原图也会随之修改，视图并非副本）
roi = img[100:200, 50:150]           

img[100:200, 50:150] = roi_processed  # 修改原图中切片选择的区域

b, g, r = cv2.split(img)              # 通道拆分（OpenCV 默认 BGR 顺序，可重新组合视化时需要）
merged_ = cv2.merge([r, g, b])        # 通道合并

# ! 在python版本的OpenCV中，尽量使数据本身的ndarray特性，效率更高，如上面的cv2.split()
b, g, r = img[:,:,0], img[:,:,1], img[:,:,2]
```

ROI 这个概念贯穿全文——不管是几何校正、缺陷检测还是分割，"先圈定感兴趣区域再处理"几乎是所有工业视觉流水线的第一个性能优化点（在第十八章"工程实践"会再强调一次这个原则）。

### 2.4 查找表（LUT）

`cv2.LUT` 用于对每个像素值按一张预先算好的映射表做变换，本质是**"空间换时间"**——避免重复计算（比如伽马变换的幂运算，预先算好 256 个可能取值对应的输出提高效率）

```python
table = np.array([((i/255.0) ** 0.5) * 255 for i in range(256)]).astype("uint8")
result = cv2.LUT(gray, table)
```

后面 3.3 节会讲到的伽马变换，就是 LUT 最典型的应用场景之一。

### 2.5 图像运算与 Normalize

```python
added = cv2.add(img1, img2)          # 饱和加法，超过255会截断在255（而非溢出回绕）
weighted = cv2.addWeighted(img1, 0.7, img2, 0.3, 0)  # 加权融合，常用于图像叠加、水印
subtracted = cv2.subtract(img1, img2)
```

这里有个新手常踩的坑：**`cv2.add` 和 NumPy 的 `+` 不是一回事**。`cv2.add` 是饱和运算（255+10 结果是 255），而 `img1 + img2`（NumPy 原生加法）在 `uint8` 类型下会发生**溢出回绕**（255+10 会变成 9），这个差异在做图像叠加、融合类操作时经常是隐藏 bug 的来源。

```python
cv2.normalize(src, dst, alpha, beta, norm_type, dtype, mask)

# 最常用的归一化当属cv2.NORM_MINMAX,这里会将img按照最大最小值放缩到[0,255]范围
# 在深度学习torchvision中，图像的转换与此类似，范围一般是[0,1]
normalized = cv2.normalize(img, None, 0, 255, cv2.NORM_MINMAX)
```

`cv2.normalize` 常用于把浮点计算结果（比如梯度幅值、距离变换结果）重新映射回 0-255 的可视化范围，在霍夫圆、频域滤波、距离变换时用到的可视化步骤，本质上都离不开这一步。

### 2.6 旋转与翻转

```python
flipped = cv2.flip(img, 1)   # 1=水平翻转，0=垂直翻转，-1=水平+垂直

rotated_90 = cv2.rotate(img, cv2.ROTATE_90_CLOCKWISE)  # 仅支持90度整数倍旋转，速度快

# 任意角度旋转需要走仿射变换（后面第三章 3.4 节会讲到的几何校正的一个特例）
# 计算图像的中心位置
center = (w // 2, h // 2)	

# 计算用于二维旋转2×3 的仿射变换矩阵（包括中心点坐标、逆时针旋转角度、图像放缩比例）
M = cv2.getRotationMatrix2D(center, angle=30, scale=1.0)  
# 通过应用变换矩阵实现仿射变换
rotated = cv2.warpAffine(img, M, (w, h))
```

`cv2.rotate` 只能做 90°/180°/270° 的整数倍旋转，任意角度旋转本质上还是要走仿射变换这条路——这和第三章的几何校正是同一套底层机制，只是应用场景更简单。

## 三、图像预处理

预处理这一步容易被低估，但据我观察，工业项目里至少一半的"检测精度问题"根源其实在预处理阶段没做好，而不是算法本身选错了。地基不稳，上层建筑盖得再花哨也白搭。当然，这里讨论的是计算机视觉而非机器视觉，对于**“图像是怎么来的”**问题并不赘述。。

### 3.1 色彩空间转换

OpenCV 读入图像**默认 BGR 通道**（不是 RGB，这是个经典的坑，新手必踩）。常用转换：

```python
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)   # 灰度化，减少计算量（使用频率最高）
hsv  = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)    # 色彩分割场景常用
lab  = cv2.cvtColor(img, cv2.COLOR_BGR2LAB)    # 光照鲁棒性更好
rgb  = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)	   # 用于可视化
```

- **灰度化**：灰度图只有单通道，能够大幅降低计算复杂度，是许多计算机视觉算法的关键预处理步骤。适用于不需要颜色信息的任务，几乎是边缘检测、图像分割、文档分析以及自适应阈值化等操作的标准前置工作。

- **HSV**：HSV空间将颜色（色调）与亮度（明度）分离，更符合人类视觉感知，对光照变化的敏感性较低，特别适合**"按颜色分拣"类任务**，比如需要分拣图中不同颜色的零件、检测红色警示标签。

  > 注意：在OpenCV中，HSV的色调(H)范围是0-179，饱和度(S)和明度(V)范围是0-255。

- **LAB**：L 通道近似人眼亮度感知，A/B 通道纯色度信息，在颜色一致性要求高的质检场景（比如**色差检测**）里比 RGB 空间更可靠。

  **颜色校正与图像分割**：LAB是一个感知均匀的色彩空间，非常适合需要测量两种颜色之间距离的任务。

  **基于颜色的聚类**：在图像分割和颜色聚类中经常被优先选择，颜色表示更符合人眼感知。

- **RGB：**OpenCV默认使用BGR格式读取图像，但其他许多图像处理库（如PIL/Pillow、Matplotlib）和显示系统使用RGB格式。进行此转换可以避免红蓝通道颠倒导致的颜色显示错误。

  > 不常用的（了解）
  >
  > YCrCb：用于视频压缩，早期也被用于肤色检测；
  >
  > HLS (色调、明度、饱和度)：类似HSV，但明度通道更符合人眼感知，适合光照变化大的场景。 CMYK (青色、品红、黄色、黑色)：主要用于打印和印刷相关的图像处理任务。

### 3.2 去噪与平滑

传统CV中的滤波去噪算法，其本质上是在"边缘信息"和"去噪强度"之间做权衡：

| 算法       | OpenCV 函数                   | 特点                             | 适用场景                           |
| ---------- | ----------------------------- | -------------------------------- | ---------------------------------- |
| 均值滤波   | `cv2.blur()`                  | 简单快速，模糊边缘               | 粗略平滑，不追求边缘保留           |
| 高斯滤波   | `cv2.GaussianBlur()`          | 加权平均，符合自然噪声分布       | 通用预处理，边缘检测前置步骤       |
| 中值滤波   | `cv2.medianBlur()`            | 对椒盐噪声极强，非线性           | 传感器噪点、扫描件去噪             |
| 双边滤波   | `cv2.bilateralFilter()`       | 保边去噪，但计算量大             | 需要平滑同时保留边缘细节的场景     |
| 引导滤波   | `cv2.ximgproc.guidedFilter()` | 双边滤波的线性时间替代，速度更快 | 大尺寸图像的实时保边滤波、抠图羽化 |
| 非局部均值 | `cv2.fastNlMeansDenoising()`  | 效果最好，速度最慢               | 离线高质量图像修复                 |

工程上一个常见的经验是：**中值滤波+高斯滤波的组合**能应对大部分工业相机的混合噪声（高斯噪声叠加脉冲噪声），比单用一种效果更稳。

> 这里的顺序一般不能变换。（先采用高斯可能导致椒盐噪声污染周围图像）

另外值得一提的是**引导滤波**（凯明大佬出品）：

定位：传统滤波 → 局部线性模型 + 盒子滤波 O(N) 实现

同样是"保边去噪"，效果接近双边滤波，但由于是线性时间复杂度实现速度更快，在大分辨率图像上表现更突出。在python环境中想要调用该算法，OpenCV 需要通过 `opencv-contrib-python` 里的 `ximgproc` 模块调用，在实时性要求高但又需要保边效果的场景（比如美颜、抠图边缘羽化）里是双边滤波的常见替代品。

### 3.3 直方图均衡化与光照归一化

工业现场的光照条件通常不理想——反光、阴影、局部过曝很常见。这一节按"全局均衡化 → 局部自适应均衡化（CLAHE）→ 非线性灰度变换 → 跨图像风格对齐 → 彩色图像"的顺序梳理常用手段。

#### 3.3.1 全局直方图均衡化

```python
equ = cv2.equalizeHist(gray)
```

适合整体偏暗/偏亮、但对比度分布相对均匀的图像；缺点是全局操作会把局部噪声一并放大，这也是为什么工业场景更常用下面的 CLAHE。

#### 3.3.2 CLAHE（限制对比度自适应直方图均衡化）

CLAHE 几乎是工业质检预处理的标配，因为它能针对图像局部区域做对比度增强，而不会像全局均衡化那样把噪声也一起放大。

**原理**：将图像分成小块（tile），对每个小块单独做直方图均衡化；为避免在平滑区域过度放大噪声，引入对比度限制（clipLimit）对直方图进行裁剪并重分配像素；最后通过双线性插值（bilinear interpolation）融合相邻块的映射结果，消除块状伪影（马赛克效应）。

```python
clahe = cv2.createCLAHE(
    clipLimit=2.0,        # 对比度限制阈值：手动调小后的常用取值
    tileGridSize=(8, 8)   # 分块网格大小，恰好是 API 的默认值
)
result = clahe.apply(gray)
```

两个参数值得展开说明：

- **`tileGridSize`（分块网格大小）**：`(8, 8)` 正是 `cv2.createCLAHE()` 的 API 默认值，绝大多数场景下直接沿用默认值即可，不太需要手动调整（这点和下面的 `clipLimit` 形成鲜明对比）。当图像尺寸不能被网格整除时，OpenCV 内部会自动做边缘镜像补齐（反射边界），将图像扩展到能被网格整除的最小尺寸，确保每个小块大小严格一致，不会产生浮点坐标。
- **`clipLimit`（对比度限制阈值）**：这是 CLAHE 区别于普通 AHE 的核心参数，用于控制局部对比度增强程度并抑制噪声放大。需要特别说明的是，`cv2.createCLAHE()` 的 **API 默认值是 `clipLimit=40.0`**，而不是网上教程里常见的 2.0——40 这个默认值几乎相当于不做裁剪限制（绝大多数直方图柱都不会被裁剪到），所以工程实践里这个参数基本不会保留默认值，几乎总是手动调小后再根据效果微调。
  - **工作机制**：若小块直方图中某灰度级的像素数超过 `clipLimit`，超出的像素会被"裁剪"并均匀重分配给其他灰度级，然后再进行均衡化映射。
  - 数值影响（均为手动设置时的经验区间，而非默认行为）：
    - **较小值（如 1.0~2.0）**：增强温和，抗噪性好，适合平滑或噪声较多的图像。
    - **适中值（如 2.0~4.0）**：常规推荐范围，能在增强细节与抑制噪声间取得平衡。
    - **较大值（如 >10.0）**：增强激进，能凸显微弱细节（如医学影像），但极易放大背景噪声并产生人工纹理。

#### 3.3.3 伽马变换与对数变换

除了直方图类操作，还有两类更基础但同样常用的非线性灰度变换：

- **伽马变换**（`cv2.pow` 或查找表实现）：$s = c \cdot r^{\gamma}$，$\gamma < 1$ 时提亮暗部细节，$\gamma > 1$ 时压暗亮部，常用于相机传感器的非线性响应校正。
- **对数变换**：$s = c \cdot \log(1+r)$，把低灰度值的范围拉伸、高灰度值的范围压缩，适合动态范围极大的图像（比如傅里叶频谱图的可视化，能量集中在极少数低频点上，不做对数变换根本看不清）。

```python
gamma = 0.5
table = np.array([((i/255.0) ** gamma) * 255 for i in range(256)]).astype("uint8")
gamma_corrected = cv2.LUT(gray, table)

log_transformed = (np.log1p(gray.astype(np.float32)) * (255 / np.log1p(255))).astype(np.uint8)
```

#### 3.3.4 直方图规定化（跨图像风格对齐）

**直方图规定化（Histogram Specification / Matching）**和均衡化的区别在于：均衡化是把直方图拉平到均匀分布，而规定化是让原图的直方图去逼近一个指定的目标分布——比如让流水线上不同批次、不同光源下拍摄的图像风格对齐到同一个参考直方图，在多工位质检系统里能有效减少"换个机位结果就不一样"的问题。

#### 3.3.5 彩色图像的光照不均衡处理

直接对 BGR 三通道分别做均衡化会导致颜色失真（比如红色变成粉色），必须转换到"亮度与颜色分离"的色空间处理，只对亮度通道做均衡化/CLAHE：

- **方案 1：HSV 空间**（工业中最常用）——V 通道（Value，亮度，0~255，与颜色无关）**仅对 V 通道做均衡化**；H（Hue）、S（Saturation）保持不变。
- **方案 2：Lab 空间**（更适合颜色敏感场景）——L 通道（Lightness，亮度，与人眼感知一致）**仅对 L 通道做均衡化**；a、b 通道（红-绿、黄-蓝对立维度）保持不变。

### 3.4 几何校正

几何校正用于消除拍摄过程中由相机姿态、镜头畸变或成像模型引起的几何失真，使图像恢复到统一的空间坐标系，是 OCR、尺寸测量、工业检测、视觉定位等任务的重要前处理步骤。

> 评价几何校正效果通常采用回归任务损失，使用未参与模型参数求解的检查点（Check Points），常用**均方根误差（RMSE）**。

#### 3.4.1 五类核心技术一览

| 技术 | 核心 API | 原理 | 典型场景 |
|---|---|---|---|
| 透视变换 | `cv2.getPerspectiveTransform` + `cv2.warpPerspective` | 根据四对对应点计算单应矩阵（Homography），校正拍摄角度造成的透视畸变 | 倾斜拍摄的文档/卡片/标签矫正为正视图，OCR、票据识别前处理 |
| 仿射变换 | `cv2.getAffineTransform` + `cv2.warpAffine` | 完成平移、旋转、缩放、错切（Shear）等线性几何变换，保持直线与平行关系 | 图像配准、目标对齐、数据增强及坐标转换 |
| 镜头畸变矫正 | `cv2.undistort` | 利用相机标定得到的内参矩阵和径向/切向畸变系数，消除桶形/枕形畸变 | 工业视觉尺寸测量、坐标映射、三维重建的前置步骤 |
| 重映射校正 | `cv2.initUndistortRectifyMap` + `cv2.remap` | 先生成像素映射关系，再用映射表完成图像重采样，性能优于每帧直接调用 `undistort` | 实时视频流去畸变、批量图像处理、双目视觉立体校正 |
| 鱼眼镜头校正 | `cv2.fisheye.calibrate`、`cv2.fisheye.undistortImage` | 针对超广角/鱼眼镜头建立专用畸变模型 | 自动驾驶环视、机器人广角避障、全景视觉 |

这五类技术在"约束强弱"上其实构成一条谱系。经典的图像变换分类体系（参考《Computer Vision: Algorithms and Applications》）把它按自由度从少到多排成一列：

- **平移**：整个图像刚性地"挪个位置"，形状、大小、朝向完全不变。
- **刚体变换**：在平移基础上增加**旋转（rotation）**，是唯一严格保持"欧氏距离"的变换，物体像刚体一样移动，不发生任何形变。
- **相似变换**：在刚体变换基础上进一步增加**均匀缩放**，全局变大变小，相对比例不变。
- **仿射变换**：在相似变换基础上，平行性保留但角度可能变化，是**图像配准、数据增强中最常用的变换之一**。
- **投影（透视）变换**：变换矩阵为 `3×3`，属于 2D 线性变换，对应真实世界中的**透视投影**效果，比如相机拍摄平面产生的形变（拍文档时纸张边缘的梯形畸变）。

每向右一级，约束越少、自由度越多、保持的几何性质越弱，但能表达的形变越丰富。这些分类在另一些教材中又常被归为 `affine` 和 `projective` 两大类，前三种都可以看作 `affine` 的特殊形式。

> 原文此处配有一张摘自《Computer Vision: Algorithms and Applications》的对比示意图（本地截图路径在整理时已失效，故以上文文字版谱系代替；如需保留原图，可自行将截图重新放回本节）。

#### 3.4.2 仿射变换与透视变换的区别

| 维度 | 仿射变换 | 透视变换 |
|---|---|---|
| 数学性质 | 线性变换，可分解为平移、旋转、缩放、错切的组合 | 模拟真实相机成像的物理过程，处理三维空间到二维平面的投影 |
| 直线/平行性 | 保持直线，保持平行关系 | 保持直线，但平行线可能相交于灭点，不再保持平行关系 |
| 是否属于"几何校正" | 通常不算严格的几何校正——不涉及物体的实际形变 | 是严格的几何校正方法，用于校正拍摄角度造成的透视畸变 |

#### 3.4.3 重采样机制

几何校正过程中，目标像素位置通常不是整数坐标，必须通过重采样确定该位置的像素值，常用三种插值方法：

1. **最近邻法（Nearest Neighbor）**：计算速度最快、精度较低，边缘可能出现锯齿。
2. **双线性内插法（Bilinear Interpolation，默认插值方法）**：效果和效率的折中，`cv2.warpAffine`/`cv2.warpPerspective`/`cv2.remap` 等函数默认都用它。
3. **三次卷积内插法（Bicubic Interpolation）**：精度最高、计算量大，可能导致图像轻微平滑或锐化。

> 重采样机制大部分时候不用手动配置，默认的双线性插值基本能覆盖绝大多数场景。

#### 3.4.4 镜头畸变的成因与分类

镜头畸变可分为**光学畸变（径向畸变、切向畸变）**和**透视畸变**两大类，成因完全不同，需要分开讨论。

**1）光学系统原因（径向畸变，Radial Distortion）**

光学畸变源于透镜设计和加工本身的物理限制：

- **透镜中心与边缘放大率不一致**：理想成像要求整个视场内放大率恒定，但实际透镜受球面像差影响，光线经过透镜边缘和中心的折射率、汇聚程度不同，导致边缘与中心的放大率出现差异。
- **有效焦距不恒定**：透镜曲率无法做到理想抛物面，实际焦距会随入射光线到光轴的距离（视场角）发生变化，而非严格意义上的常数。
- **孔径光阑偏离光学系统几何中心**：加工装配误差导致光阑（控制光线通过量的部件）与镜片光轴不重合，引入**切向畸变（Tangential Distortion）**，表现为图像沿某一方向的非对称扭曲。

由此产生两种典型径向畸变：

| 类型 | 表现 | 常见于 |
|---|---|---|
| **桶形畸变** | 图像边缘相对中心向外膨胀，直线变凸 | 广角/鱼眼镜头 |
| **枕形畸变** | 图像边缘相对中心向内收缩，直线变凹 | 长焦/望远镜头 |

成因本质：放大率随离光轴距离的变化规律不同——广角镜头边缘放大率小于中心（桶形），长焦镜头边缘放大率大于中心（枕形）。

**2）拍摄条件原因（透视畸变，Perspective Distortion）**

这一类**不属于镜头光学缺陷**，而是拍摄几何关系导致的正常透视效应：

- **相机光轴与被摄平面不垂直**（拍摄角度倾斜），导致物体不同部位到相机的距离不同。
- 距离近的部分在像平面上成像更大，距离远的部分成像更小，从而产生**透视变形**。
- 典型场景：仰拍高层建筑导致线条汇聚；平视角度不正拍摄文档/票据，导致原本的矩形在图像中呈现梯形（这也是文档矫正、透视变换纠正的处理对象）。

**3）OpenCV 中两套完全独立的处理流程**

光学畸变（径向+切向）和透视畸变在 OpenCV 中对应两套完全不同的处理流程：**相机标定去畸变**处理光学畸变，**透视变换**处理透视畸变。两者不可混用——透视变换无法修复镜头本身的桶形/枕形畸变，标定去畸变也无法修正拍摄角度导致的透视形变。

#### 3.4.5 畸变数学模型

OpenCV 采用如下畸变模型，将径向畸变与切向畸变统一表达：

**径向畸变（Radial Distortion）：**
$$ x_{corrected} = x(1 + k_1 r^2 + k_2 r^4 + k_3 r^6) $$
$$ y_{corrected} = y(1 + k_1 r^2 + k_2 r^4 + k_3 r^6) $$

**切向畸变（Tangential Distortion）：**
$$ x_{corrected} = x + [2p_1 xy + p_2(r^2 + 2x^2)] $$
$$ y_{corrected} = y + [p_1(r^2 + 2y^2) + 2p_2 xy] $$

其中 $r^2 = x^2 + y^2$（点到光轴中心的归一化距离平方），$k_1, k_2, k_3$ 为径向畸变系数，$p_1, p_2$ 为切向畸变系数。OpenCV 将五个系数打包为一个畸变向量：`[k1, k2, p1, p2, k3]`。

#### 3.4.6 相机标定与去畸变实现

标定的核心思路是拍摄多张**已知真实尺寸的棋盘格**图像，通过检测角点在图像中的实际位置与理论无畸变位置的偏差，反解出相机内参矩阵和畸变系数。OpenCV 实现流程：

1. **角点检测**：`cv2.findChessboardCorners` 查找棋盘格内角点。
2. **亚像素精细化**：`cv2.cornerSubPix` 提升角点检测精度。
3. **执行标定**：`cv2.calibrateCamera` 求解相机内参矩阵（含等效焦距和主点坐标）、畸变系数以及外参（旋转向量和平移向量），并返回重投影误差。

标定建议采集 15~20 张覆盖不同角度与位置的图像，重投影误差通常应控制在 0.1~1.0 像素以内。标定结果可通过常规文件方式（如 NumPy 的 npz 格式）保存与复用；只要光学系统（焦距、镜头）不变，标定结果就能稳定复用，一旦更换镜头或相机发生撞击、形变等物理变化，则必须重新标定。

获得标定参数后，即可对图像做去畸变处理，核心 API 包括：

- **最优矩阵计算**：`cv2.getOptimalNewCameraMatrix`，计算新的相机矩阵，可通过 alpha 参数控制是否裁剪边缘黑边。
- **直接去畸变**：`cv2.undistort`，适合单张图像偶尔处理，代码简洁直观。
- **预计算映射 + 重映射**：针对视频流或批量图像，用 `cv2.initUndistortRectifyMap` 预先生成映射表 `(map1, map2)`，然后对每帧调用 `cv2.remap` 做快速处理——本质上是"空间换时间"，避免每帧都重复求解畸变公式，性能明显优于逐帧直接调用 `cv2.undistort()`。

> 本节的相机标定流程，也正是第十章「[10.1 相机标定](#101-相机标定)」里"张正友标定法"用到的具体实现细节——两节分别从"预处理去畸变"和"三维视觉基础"两个角度使用同一套标定结果，避免重复展开。

#### 3.4.7 透视变换实现与自动角点检测

透视畸变的校正不使用畸变系数，而是通过标定四个已知对应点求解单应性矩阵：

1. **求解变换矩阵**：`cv2.getPerspectiveTransform`，输入原图四个角点与目标矩形的四个角点，输出 3×3 的单应性矩阵。
2. **应用透视变换**：`cv2.warpPerspective`，根据矩阵将原图映射到目标尺寸。

若需要自动检测文档/票据的四个角点，理论流程通常结合边缘检测（`cv2.Canny`，见「[5.1 边缘检测](#51-边缘检测)」）、轮廓提取（`cv2.findContours`，见「[5.2 轮廓提取与几何描述](#52-轮廓提取与几何描述)」）与多边形逼近（`cv2.approxPolyDP`），并需特别注意对提取到的角点按几何位置（如左上、右下）排序，避免图像镜像或旋转错乱。

#### 3.4.8 两类畸变校正对比总结

| 维度 | 光学畸变校正 | 透视畸变校正 |
|---|---|---|
| **成因** | 镜头光学系统缺陷 | 拍摄角度/相机与物体不垂直 |
| **核心函数** | `cv2.calibrateCamera` + `cv2.undistort` | `cv2.getPerspectiveTransform` + `cv2.warpPerspective` |
| **所需输入** | 多张棋盘格标定图 | 单张图 + 四个对应点坐标 |
| **变换性质** | 非线性（径向/切向多项式模型） | 线性齐次变换（3×3 矩阵，DoF=8） |
| **是否与相机绑定** | 是（同一相机/镜头标定一次即可复用） | 否（每张图根据具体透视关系单独求解） |
| **典型场景** | 广角镜头拍摄的桶形畸变、工业相机镜头校正 | 文档扫描矫正、倾斜拍摄的票据/白板矫正 |

实际工程流程中，若同时存在两种畸变（比如用广角相机倾斜拍摄文档），正确顺序应为：**先用光学去畸变流程消除镜头本身的物理缺陷，再用透视变换校正拍摄角度问题**，顺序颠倒会导致透视变换基于已扭曲的图像计算，引入额外误差。

#### 3.4.9 工程实践建议

**性能与精度**

- 对于需要重复执行的畸变校正任务，优先使用 3.4.6 讲到的重映射（remap）方案；实时视频处理中，它比逐帧调用 `cv2.undistort()` 更高效。
- 插值方法可根据精度需求选择，多数场景下默认的双线性插值（`INTER_LINEAR`）已经足够。

**应用场景选择**

- 文档处理：通常需要先做镜头去畸变，再用透视变换（四点对应）恢复正视图，这也是手机扫描类应用的标准处理流程。
- 工业测量：镜头畸变会直接影响测量精度，必须进行校正。
- 自动驾驶：环视泊车辅助等场景常使用鱼眼镜头，需要专门的鱼眼相机模型（`cv2.fisheye` 模块），而非普通针孔相机的畸变模型。
- 实时监控：采用预计算的重映射方案，以查表代替重复计算，保证处理效率。

> **重要提示**：几何变换（畸变校正、透视变换等）通常是图像处理流水线中的前置步骤，直接决定后续算法（检测、测量、识别等）能否正常工作。在设计视觉系统时，应当把几何校正环节的实现和优化放在与核心算法同等重要的位置。

## 四、特征提取与描述子

传统计算机视觉进行特征提取的核心问题是：如何用一组**稳定的数值向量描述图像中某个局部区域**，使同一目标在不同尺度、旋转、光照甚至一定程度视角变化下仍能被可靠匹配。

随着以 CNN、Vision Transformer（ViT）等深度学习方法的发展，在图像分类、目标检测、图像检索等任务中，人工设计的局部特征描述子已逐渐被网络自动学习的深层特征所取代。但在视觉 SLAM、图像拼接、三维重建、工业视觉定位、模板匹配以及资源受限的嵌入式设备等场景中，SIFT、ORB、AKAZE 等传统特征描述子仍然具有重要的工程价值。

> 注意！在特征提取阶段，`opencv-python`不完全，需要`pip install opencv-contrib-python`

### 4.1 角点检测

角点是图像中信息量最密集的区域（在两个方向上灰度变化都剧烈），可作为跟踪、匹配的锚点，包括：

- **Harris 角点**（`cv2.cornerHarris`）：最经典的角点响应函数，基于局部自相关矩阵的特征值。
- **Shi-Tomasi**（`cv2.goodFeaturesToTrack`）：Harris 的改进版，直接用较小特征值作为角点响应，工程上更常用，因为参数直观（最大角点数、质量阈值、最小间距）。
- **FAST**（`cv2.FastFeatureDetector_create()`）：只比较圆周上一圈像素与中心像素的灰度关系，不涉及矩阵特征值分解，检测速度极快，是 ORB 描述子里角点检测这一半的来源（ORB = FAST 角点 + BRIEF 描述子的旋转不变版本），对实时性要求极高的场景（比如高帧率视频流的特征跟踪）首选。

```python
corners = cv2.goodFeaturesToTrack(gray, maxCorners=100, qualityLevel=0.01, minDistance=10)
```

### 4.2 局部特征描述子

这是传统 CV 里最"硬核"的一块，该特征常用于**图像匹配、全景拼接、SLAM 前端**。

| 算法 | 特点 | 是否专利/许可 | OpenCV 接口 |
|---|---|---|---|
| SIFT | 尺度、旋转不变性极强，精度高 | 专利已过期，现已默认可用 | `cv2.SIFT_create()` |
| SURF | SIFT 的加速版 | 仍受专利限制，需自编译 opencv-contrib | `cv2.xfeatures2d.SURF_create()` |
| ORB | 二进制描述子，速度极快 | 完全免费开源 | `cv2.ORB_create()` |
| AKAZE | 非线性尺度空间，边缘保留更好 | 免费 | `cv2.AKAZE_create()` |
| BRISK | 二进制描述子，介于 ORB 和 SIFT 之间 | 免费 | `cv2.BRISK_create()` |

一个很实用的经验法则：**实时性要求高（比如移动端、嵌入式）选 ORB；精度要求高、离线处理选 SIFT；两者之间的折中选 AKAZE**。

```python
sift = cv2.SIFT_create()
keypoints, descriptors = sift.detectAndCompute(gray, None)
```

角点之外还有一类**斑点（Blob）检测**算法值得单独提一下：**MSER（最大稳定极值区域）**（`cv2.MSER_create()`），它通过对图像做一系列阈值扫描，找到那些在很大阈值范围内面积保持稳定的连通区域。MSER 对仿射变换有较好的不变性，常用于文字区域检测（车牌、场景文字）和某些形变不大的目标定位场景，是 SIFT/ORB 这类"角点式"特征之外的另一条技术路线。

### 4.3 纹理与统计特征

除了关键点描述子，还有一类基于统计分布的纹理特征，常用于分类和缺陷检测：

- **LBP（局部二值模式）**：编码每个像素与其邻域的相对灰度关系，对光照变化鲁棒，是人脸识别、材质分类的经典特征（OpenCV 中常配合 `scikit-image` 使用，OpenCV 自身在 `face` 模块里也有实现）。
- **HOG（方向梯度直方图）**：统计局部区域的梯度方向分布，是**经典的行人检测器的核心特征**，HOG+SVM的组合也是很经典的案例。

```python
hog = cv2.HOGDescriptor()
features = hog.compute(gray)
```

- **GLCM（灰度共生矩阵）**：描述像素对之间的空间关系统计量，常用于**表面粗糙度、材质纹理分析**——这个在工业表面质检里出场率很高，比如**判断一块金属表面是否有异常纹理**。
- **Gabor 滤波器**：一组模拟人类视觉皮层感受野特性的带通滤波器，同时具备特定的方向和频率选择性，用一组不同方向、不同尺度的 Gabor 核卷积图像，能提取出方向敏感的纹理特征。常用于指纹识别（脊线方向提取）、织物瑕疵检测（正常纹理有规律方向性，瑕疵会打破这种规律）。

```python
kernel = cv2.getGaborKernel(ksize=(21,21), sigma=5, theta=np.pi/4, lambd=10, gamma=0.5)
filtered = cv2.filter2D(gray, cv2.CV_8UC3, kernel)
```

### 4.4 形状描述子

除了局部特征点，还有一类专门描述"整体轮廓形状"的描述子，在形状分类、字符识别、细胞形态学分析里很常用：

- **Hu 不变矩**（`cv2.HuMoments(cv2.moments(cnt))`）：基于图像矩构造出的 7 个组合量，对平移、旋转、缩放都保持不变，是最经典的"用一组数字描述形状"的方法，常用于简单形状分类（比如区分螺丝、螺母、垫片这类差异明显的零件轮廓）。
- **Zernike 矩**：基于正交多项式基的矩特征，比 Hu 矩具有更强的形状描述能力和抗噪性，计算量也更大，常见于细胞核形态分析、字符识别中的形状特征提取。
- **Fourier 描述子**：把轮廓的边界点序列看作复数序列做傅里叶变换，用低频系数就能重建出轮廓的整体形状趋势，天然具备平移不变性，旋转和缩放不变性通过归一化处理获得，常用于叶片形状分类、工件轮廓比对这类任务。
- **链码（Chain Code）**：把轮廓编码成一串方向序列（比如 8 邻域链码用 0-7 表示八个方向），是最古老也最紧凑的轮廓表示方法之一，常作为形状匹配、轮廓压缩存储的基础表示。

### 4.5 频域特征与滤波

傅里叶变换（`cv2.dft` / `cv2.idft`）能把图像从空间域转到频域，高频对应边缘/噪声/细节，低频对应整体轮廓/光照。频域视角下能做的事情，比单纯"提特征"要丰富得多：

```python
dft = cv2.dft(np.float32(gray), flags=cv2.DFT_COMPLEX_OUTPUT)
dft_shift = np.fft.fftshift(dft)  # 低频移到中心，便于观察和设计滤波器
magnitude = 20 * np.log(cv2.magnitude(dft_shift[:,:,0], dft_shift[:,:,1]) + 1)
```

- **低通滤波**：保留中心低频区域，滤掉高频细节，起到平滑降噪的作用，效果类似空域的高斯模糊，但对某些周期性噪声更有针对性。
- **高通滤波**：保留边缘高频，滤掉低频背景，用于突出细节和边缘。
- **带阻滤波 / 陷波滤波（Notch Filter）**：频谱图上，周期性的规律噪声（比如电网工频干扰导致的条纹、扫描仪机械振动导致的摩尔纹）会在特定频率上表现为明显的亮点，陷波滤波就是精确地把这几个亮点"抠掉"，在医学 X 光/CT 图像去条纹伪影中是经典手段。

#### 4.5.1 频域去噪：什么时候值得"上频域"

低通滤波能去噪不假，但工程上一个常被忽略的问题是——**大部分随机噪声（高斯噪声、传感器噪点）用空域高斯滤波/中值滤波就够了，频域低通滤波在这类场景下并不比空域方法更有优势**，反而多了一次正变换+滤波+逆变换的计算开销。频域方法真正的价值在于**噪声本身具有明确的频率特征**的场景：

- **周期性噪声**（电网工频干扰的条纹、扫描仪机械振动导致的摩尔纹、面阵相机的读出噪声条纹）：这类噪声在频谱图上会表现为集中的孤立亮点，用陷波滤波可以精确地把这几个点"抠掉"，而空域滤波（无论高斯还是中值）无法做到这种"频率选择性"操作，要么伤害真实细节，要么去不干净。
- **需要同时观察噪声的频率成分**（比如判断某种周期性纹理异常是否属于设备机械振动导致的干扰）：频谱图本身就是一种诊断工具，空域滤波给不出这个视角。

反过来，如果噪声本身是空间上随机、没有明显频率结构的（典型的高斯噪声、椒盐噪声），空域滤波通常在效果和计算量上都更划算——这也是为什么第三章讲预处理时优先介绍的是空域滤波，而不是频域方法。判断要不要上频域去噪，一个简单的经验法则是：**先看频谱图上有没有明显的孤立亮点/条纹，有就用频域陷波滤波精确打击，没有就老老实实用空域滤波**。

除了傅里叶变换，**小波变换（Discrete Wavelet Transform, DWT）**提供了另一种频域分析工具，和傅里叶变换"只有频率信息、丢失空间位置"不同，小波变换能同时保留时间/空间与频率的局部信息，把图像分解成不同尺度下的近似分量与细节分量（水平、垂直、对角三个方向）：

```python
import pywt
coeffs = pywt.dwt2(gray, 'haar')
cA, (cH, cV, cD) = coeffs   # 近似 + 水平/垂直/对角细节
```

小波变换是 JPEG2000 压缩标准的核心基础，也常用于多分辨率图像融合（比如把不同曝光度的照片在小波域里融合，得到 HDR 效果）、图像去噪（对细节分量做阈值收缩，再重建）。这部分内容在通用工业质检里不算高频出场，但在图像压缩、医学影像多分辨率分析领域是绕不开的工具。上面使用了`pywt.dwt2`，实际上pywt在信号处理领域同样可以处理一维数据，但这里我们仅关注二维图像。

### 4.6 传统特征提取的解构

回顾前述的四类经典特征提取方法，一个核心的认知误区需要被澄清：**传统特征提取并非仅仅局限于对原始像素矩阵的空间域操作，而是横跨了空间域、频域（变换域）以及统计域的多维正交解构。**

在具体的算法实现中，这种多维度的数学思想体现得淋漓尽致：

- **纯空间域操作**：如 Harris 角点、LBP、HOG 以及 Hu 矩等，它们严格限制在局部物理坐标内，通过梯度计算、邻域比较或空间积分来刻画图像的几何与灰度突变。
- **频域与变换域映射**：以 Gabor 滤波器和 Fourier 描述子为代表。它们突破了空间坐标的局限，Gabor 滤波器在空间域执行卷积，其本质却是对特定空间频率和方向的频域提取（时频局部化）；而 Fourier 描述子则直接将轮廓序列视为一维信号进行傅里叶变换，用频域系数重构形状。
- **统计域与特征空间**：GLCM 通过计算空间像素对的联合概率来提取拓扑结构；而词袋模型（BoVW）更是彻底打破了原始的空间坐标限制，将局部特征映射到高维聚类空间，最终转化为定长的语义统计向量。

**从传统到智能的脉络延续**
深入理解这种多维度的特征解构，不仅有助于夯实计算机视觉的底层数学基础，更能洞察现代深度学习的发展脉络。事实上，深度学习中的卷积神经网络（CNN）并非凭空出现，其卷积核在本质上就是**空间域内“可学习的 Gabor 滤波器”**。传统方法中对尺度、旋转不变性的严谨数学设计，直接启发了现代网络中池化层与数据增强的演进。

在数据量有限、计算资源受限或需要高可解释性的特定场景（如工业缺陷质检、医学影像分析）中，传统多维特征与深度学习的融合往往能发挥出比纯端到端模型更优异的性能。因此，传统特征提取不仅是计算机视觉发展史上的璀璨明珠，更是指导我们设计高效、鲁棒视觉系统的重要理论基石。

## 五、边缘、轮廓与形状分析

如果说特征描述子是"识别身份"，那边缘和轮廓分析要解决的就是"确定形状与边界"——这一类算法在工业测量、缺陷定位场景里几乎是刚需。

### 5.1 边缘检测

| 算法 | 原理 | OpenCV 函数 | 特点 |
|---|---|---|---|
| Sobel | 一阶梯度算子 | `cv2.Sobel()` | 简单、方向可分离（水平/垂直） |
| Prewitt | 一阶梯度算子（Sobel 的等权版本） | （OpenCV 无直接 API，卷积核自定义） | 简单快速，教学/快速原型常用 |
| Laplacian | 二阶导数算子 | `cv2.Laplacian()` | 对噪声敏感，常配合高斯先平滑 |
| Canny | 多阶段：高斯平滑→梯度→非极大值抑制→双阈值滞后 | `cv2.Canny()` | 工程界事实标准，边缘细而连续 |
| Scharr | Sobel 的优化版，精度更高 | `cv2.Scharr()` | 小尺度核下比 Sobel 更准确 |

Canny 几乎是"边缘检测"的代名词，原因很简单——它自带的双阈值滞后机制能有效抑制断续边缘和虚假响应：

```python
edges = cv2.Canny(gray, threshold1=50, threshold2=150)
```

这里有个很实际的调参经验：**threshold1:threshold2 的比例一般取 1:2 或 1:3**，具体数值需要结合图像对比度反复试，没有放之四海而皆准的黄金参数——这也是传统 CV 常被吐槽"太依赖人工调参"的地方，但反过来说，可调也意味着可控。

### 5.2 轮廓提取与几何描述

拿到边缘之后，往往还需要把它们组织成"轮廓"（闭合或开放的点集），这样才能进一步做面积、周长、形状的定量分析。

```python
contours, hierarchy = cv2.findContours(binary_img, cv2.RETR_TREE, cv2.CHAIN_APPROX_SIMPLE)

for cnt in contours:
    area = cv2.contourArea(cnt)
    perimeter = cv2.arcLength(cnt, True)
    x, y, w, h = cv2.boundingRect(cnt)          # 外接矩形
    (cx, cy), radius = cv2.minEnclosingCircle(cnt)  # 最小外接圆
    rect = cv2.minAreaRect(cnt)                  # 最小外接旋转矩形
    hull = cv2.convexHull(cnt)                   # 凸包
    approx = cv2.approxPolyDP(cnt, epsilon=0.02*perimeter, closed=True)  # 多边形近似
```

这一套 API 组合起来几乎能覆盖大部分"形状判定"类任务：圆度检测（面积与最小外接圆面积之比）、矩形度检测、多边形边数判断（比如区分三角形、四边形、六边形零件）。

### 5.3 霍夫变换：从像素到几何参数

霍夫变换是传统 CV 里一个非常优雅的思想——把"图像空间中寻找几何形状"转化为"参数空间中寻找峰值"。

- **霍夫直线变换**（`cv2.HoughLines` / `cv2.HoughLinesP`）：检测直线，常用于车道线检测、文档边框检测、PCB 走线检测。
- **霍夫圆变换**（`cv2.HoughCircles`）：检测圆形，硬币计数、瓶盖检测、圆形零件定位的经典方案。

```python
lines = cv2.HoughLinesP(edges, 1, np.pi/180, threshold=50, minLineLength=50, maxLineGap=10)
circles = cv2.HoughCircles(gray, cv2.HOUGH_GRADIENT, dp=1, minDist=20,
                             param1=50, param2=30, minRadius=5, maxRadius=50)
```

嗯，值得一提的是，霍夫圆变换对参数相当敏感，实际项目里经常需要先做边缘增强、再限定半径范围，否则容易出现大量误检——这也是很多新手第一次用 `HoughCircles` 时踩坑最多的地方。

### 5.4 亚像素级精度：当整数像素不够用的时候

前面讲的边缘检测、角点检测，输出的坐标默认都是整数像素精度。但在高精度工业测量场景里（比如测量一个孔径是否符合 ±0.01mm 的公差），整数像素的分辨率往往不够用——这时候就需要**亚像素级（Sub-pixel）精度**的优化。

对角点，OpenCV 提供了现成的亚像素级优化函数：

```python
corners = cv2.goodFeaturesToTrack(gray, maxCorners=50, qualityLevel=0.01, minDistance=10)
criteria = (cv2.TERM_CRITERIA_EPS + cv2.TERM_CRITERIA_MAX_ITER, 30, 0.001)
corners_subpix = cv2.cornerSubPix(gray, corners, winSize=(5,5), zeroZone=(-1,-1), criteria=criteria)
```

对边缘/轮廓，常见的亚像素修正思路是在边缘点邻域内对灰度梯度做二次曲面拟合，取拟合曲面的极值点位置作为亚像素级边缘位置——这一步 OpenCV 没有直接封装的通用 API，工业相机 SDK（如海康、大恒的机器视觉库）或 HALCON 这类商业库通常会内置更完善的亚像素边缘提取算法。

理解这个概念的意义在于：**测量类任务的精度上限，不是由相机分辨率决定的，而是由算法能不能做亚像素级插值决定的**，这也是传统 CV 在精密尺寸测量领域相比深度学习模型（输出通常停留在像素或格子精度）仍有明显优势的地方。

## 六、图像分割

分割要解决的是"哪些像素属于同一个对象/区域"这个问题，是从"点"到"面"的关键一跳。

### 6.1 阈值分割

最基础也最常用的一类方法，核心思路是找一个（或多个）灰度阈值，把图像切成前景/背景：

```python
# 全局固定阈值
_, binary = cv2.threshold(gray, 127, 255, cv2.THRESH_BINARY)

# Otsu 自动阈值（大津法），基于类间方差最大化自动求阈值
_, binary = cv2.threshold(gray, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)

# 自适应阈值，逐块计算局部阈值，应对光照不均
adaptive = cv2.adaptiveThreshold(gray, 255, cv2.ADAPTIVE_THRESH_GAUSSIAN_C,
                                   cv2.THRESH_BINARY, blockSize=11, C=2)
```

补充两种在工程里也会遇到的阈值策略：

- **三角阈值法（Triangle Thresholding）**：更适合“单峰偏态”的直方图分布（比如背景占绝大多数、前景只占很小比例的场景）。OpenCV 直接支持：

  ```python
  _, binary = cv2.threshold(gray, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_TRIANGLE)
  ```

- **双峰阈值法（Bimodal Thresholding）**：当直方图存在两个明显峰值时，常用做法是寻找两峰之间的“谷底”作为阈值（可以手动设定，也可以做直方图平滑后自动找 valley）。它本质上是对“Otsu 适用条件”的一种更直观实现。

Otsu 法是工业质检里出场率最高的分割方法之一，因为它不需要人工设定阈值，能根据图像的直方图分布自动找到"类间方差最大"的分割点，前提是图像的前景背景灰度分布确实呈双峰状——如果光照不均匀，就得上自适应阈值。OpenCV 内置的自适应阈值本质上是局部均值/高斯加权阈值，还有一种在文档二值化领域更常用的**Sauvola 局部阈值算法**（`cv2.ximgproc.niBlackThreshold` 里可以选择 Sauvola 模式，或用 `scikit-image` 的 `threshold_sauvola`），它在局部均值的基础上引入了局部标准差作为动态调节项，对纸张褶皱、墨迹浓淡不均的扫描文档二值化效果比普通自适应阈值更稳健，OCR 前处理里经常会用到。

### 6.2 超像素：SLIC

在讲区域分割之前，有必要单独介绍一下**超像素（Superpixel）**这个概念——它不是最终分割结果，而是一种"预分组"策略：把图像里颜色、位置都相近的像素聚成一个个不规则小块（超像素），用超像素代替原始像素做后续处理，能大幅降低计算复杂度，同时又比规则网格分块更贴合物体的真实边界。

**SLIC（简单线性迭代聚类）**是目前最主流的超像素算法，思路是把 K-Means 聚类从颜色空间（3维 RGB/LAB）扩展到"颜色+坐标"的 5 维空间（L, a, b, x, y），并且把搜索范围限制在每个聚类中心的局部邻域内，因此速度比全图 K-Means 快得多。

```python
slic = cv2.ximgproc.createSuperpixelSLIC(img, algorithm=cv2.ximgproc.SLICO, region_size=20)
slic.iterate(num_iterations=10)
labels = slic.getLabels()          # 每个像素所属的超像素编号
mask = slic.getLabelContourMask()  # 超像素边界掩码，用于可视化
```

SLIC 的典型用法有两种：一是作为深度学习模型的前处理，把像素级任务降维成超像素级任务，减少计算量；二是在医学影像里配合区域生长做"预分割"，先把图像切成小块，再对每个超像素块统计纹理/灰度特征，用统计距离（比如马氏距离）判断该块是否异常——这套思路在表面缺陷检测、医学 ROI 粗定位里都很常见，本文第十六章会给出具体的组合流程。

### 6.3 区域生长与区域合并

**区域生长（Region Growing）**是一种更"直觉化"的分割思路：从一个或多个种子点出发，按照某种相似性准则（灰度差、颜色距离、纹理相似度）不断把相邻像素并入当前区域，直到没有像素满足合并条件为止。

```python
def region_growing(img, seed, threshold=10):
    # 伪代码逻辑：从种子点出发，BFS 扩展满足灰度差阈值条件的邻域像素
    # OpenCV 没有直接封装该算法，通常基于 floodFill 或自行实现队列扩展
    mask = np.zeros((img.shape[0]+2, img.shape[1]+2), np.uint8)
    cv2.floodFill(img, mask, seed, 255, loDiff=threshold, upDiff=threshold)
    return mask
```

`cv2.floodFill` 本质上就是一种简化版的区域生长（种子填充），在医学影像中勾画病灶轮廓、遥感图像中提取同质地块（比如同一块农田、同一片水域）时很常用，好处是逻辑直观、易于人工干预（医生点一下种子点就能生长出病灶范围），缺点是对种子点选择和相似性阈值比较敏感。

与之相对的是**区域合并（Region Merging）**，从相反方向出发：先把图像过分割成很多小区域（比如用 SLIC 生成超像素），再根据相邻区域的相似性逐步合并，直到满足停止条件——这种"先分后合"的策略在复杂纹理图像分割中往往比单纯的区域生长更稳健，因为不需要精心挑选种子点。

### 6.4 基于区域的经典分割算法

- **分水岭算法**（`cv2.watershed`）：把图像看作地形图，从"种子点"开始"灌水"，直到不同区域的水汇合形成分割边界。特别适合**粘连目标的分离**，比如显微镜下粘连的细胞、堆叠的颗粒物——这也是很多计数类任务（比如统计颗粒数量）绕不开的算法。
- **GrabCut**（`cv2.grabCut`）：基于图割（Graph Cut）的交互式前景提取，只需要粗略框选一个矩形区域，算法就能迭代求解出精细的前景掩码，常用于抠图类应用。
- **均值漂移分割**（`cv2.pyrMeanShiftFiltering`）：基于颜色空间聚类的分割，对纹理复杂但颜色区分明显的图像效果不错。

### 6.5 分水岭 + 距离变换的经典组合

这个组合值得单独拎出来讲一下，因为它是解决"粘连目标分割"最经典的传统 CV 套路：

```python
# 1. 二值化
_, thresh = cv2.threshold(gray, 0, 255, cv2.THRESH_BINARY_INV + cv2.THRESH_OTSU)

# 2. 形态学开运算去噪
kernel = np.ones((3,3), np.uint8)
opening = cv2.morphologyEx(thresh, cv2.MORPH_OPEN, kernel, iterations=2)

# 3. 距离变换，找到每个粘连区域的"核心"
dist_transform = cv2.distanceTransform(opening, cv2.DIST_L2, 5)
_, sure_fg = cv2.threshold(dist_transform, 0.7*dist_transform.max(), 255, 0)

# 4. 确定未知区域，做标记
sure_fg = np.uint8(sure_fg)
unknown = cv2.subtract(opening, sure_fg)
_, markers = cv2.connectedComponents(sure_fg)
markers = markers + 1
markers[unknown == 255] = 0

# 5. 分水岭分割
markers = cv2.watershed(img, markers)
```

这套流程在细胞计数、颗粒物计数、粘连零件分离等场景里算是经典的SOP了。

### 6.6 GrabCut 交互式分割

```python
mask = np.zeros(img.shape[:2], np.uint8)
bgdModel = np.zeros((1, 65), np.float64)
fgdModel = np.zeros((1, 65), np.float64)
rect = (50, 50, 300, 300)  # 初始矩形框
cv2.grabCut(img, mask, rect, bgdModel, fgdModel, iterCount=5, mode=cv2.GC_INIT_WITH_RECT)
mask2 = np.where((mask == 2) | (mask == 0), 0, 1).astype('uint8')
result = img * mask2[:, :, np.newaxis]
```

GrabCut 在产品图抠图、证件照背景替换类应用中很常见，效果虽然不如深度学nnunet等分割模型精细，但胜在不需要训练数据、计算成本低。

## 七、目标检测

在 R-CNN、YOLO 系列成为主流之前，目标检测这个问题是怎么解决的？回顾一下这段历史挺有意思的，而且这些方法至今在特定场景（尤其是样本稀缺、类别单一）下依然能用。

### 7.1 模板匹配

最朴素的检测思路——拿一个模板图在目标图像上滑动，计算相似度：

```python
result = cv2.matchTemplate(img, template, cv2.TM_CCOEFF_NORMED)
min_val, max_val, min_loc, max_loc = cv2.minMaxLoc(result)
```

模板匹配的局限很明显（不支持旋转缩放，除非做多尺度金字塔搜索），但对于**固定视角、固定姿态的工业场景**（比如 PCB 上固定位置的元件定位、包装盒上 Logo 位置校验），依然是性价比极高的方案，快、准、不需要训练。

### 7.2 级联分类器（Haar / LBP + AdaBoost）

Viola-Jones 框架曾经是人脸检测的事实标准，核心思想是用 Haar 特征 + AdaBoost 级联弱分类器，逐级过滤掉明显不是目标的区域，提升效率：

```python
face_cascade = cv2.CascadeClassifier(cv2.data.haarcascades + 'haarcascade_frontalface_default.xml')
faces = face_cascade.detectMultiScale(gray, scaleFactor=1.1, minNeighbors=5)
```

虽然现在人脸检测基本被深度学习模型（如 MTCNN、RetinaFace）取代了，但级联分类器的**训练成本极低**（自己的数据集上几十分钟就能训出一个专用检测器），在某些资源受限、类别单一的嵌入式场景里仍有一席之地。

### 7.3 HOG + SVM

经典的行人检测方案：用 HOG 提取梯度方向直方图特征，再喂给 SVM 分类器做二分类判断：

```python
hog = cv2.HOGDescriptor()
hog.setSVMDetector(cv2.HOGDescriptor_getDefaultPeopleDetector())
boxes, weights = hog.detectMultiScale(img, winStride=(8,8))
```

HOG+SVM 的思路（手工特征 + 传统分类器）某种程度上是深度学习检测器的"精神祖先"——理解它有助于理解后来的 R-CNN 系列为什么要"用卷积网络自动学特征取代手工特征"这个核心突破点。

### 7.4 滑动窗口 + 图像金字塔

在没有 Anchor、没有 RPN 的年代，检测不同尺度的目标依赖构建图像金字塔（`cv2.pyrDown` / `cv2.pyrUp`），在每一层金字塔上用固定大小的窗口滑动扫描，再对每个窗口做分类判断。这个思路计算量大、效率低，但逻辑简单直接，理解它有助于理解为什么"多尺度检测"是个如此重要的问题，也是后来 FPN（特征金字塔网络）设计动机的直接来源。

图像金字塔与多尺度相对应，滑动窗口的方法在近些年依旧被广泛提及和使用，这俩的应用场景也及其相似，尤其对于遥感等高分辨率领域。刚好最近在做高分辨率大图的钻石识别和缺陷检测、平整度判断等，就用到了滑动窗口的思想`SAHI`（https://arxiv.org/abs/2202.06934）

### 7.5 词袋模型（Bag of Visual Words）

在深度学习分类器普及之前，图像分类问题的经典解法是"词袋模型"（BoVW），思路借鉴自文本分类领域的词袋思想：

```
大量训练图像 → 逐图提取SIFT/ORB局部特征 → 汇总所有描述子做K-Means聚类
        → 聚类中心构成"视觉词典"(Visual Vocabulary)
        → 每张图统计各视觉单词出现频次，得到一个定长直方图向量
        → 直方图向量喂给SVM/随机森林做分类
```

```python
bow_trainer = cv2.BOWKMeansTrainer(clusterCount=100)
# 逐张图像提取SIFT描述子后 bow_trainer.add(descriptors)
vocabulary = bow_trainer.cluster()

bow_extractor = cv2.BOWImgDescriptorExtractor(sift, cv2.BFMatcher(cv2.NORM_L2))
bow_extractor.setVocabulary(vocabulary)
hist = bow_extractor.compute(gray, keypoints)  # 得到定长直方图特征
```

BoVW 的精妙之处在于，它把"数量不固定的局部特征点"转化成了"固定长度的全局特征向量"，从而能直接喂给传统分类器——这个"局部特征→聚类→全局统计直方图"的思路，其实和后来深度学习里的 NetVLAD、图像检索中的 VLAD 编码在精神上是一脉相承的，理解 BoVW 有助于理解这条技术脉络的延续性。

> 在自然语言处理领域中忽略语法和次序，仅关注词汇的出现频次，该思想最基础的表达就是早期的**One-Hot 编码** 和**TF-IDF**。
>
> 通常会配合朴素贝叶斯、SVM等传统机器学习模型进行分类，进一步为了填充**语义鸿沟**（同义词、上下文顺序）衍生出一系列包括：N-gram、潜在语义分析等（这部分在介绍数学之美时有所提及https://zhuanlan.zhihu.com/p/1976670215124325037），接着是`skip-gram`和`CBOW`，逐渐往embedding方向发展。

### 7.6 可变形部件模型（DPM）

**DPM（Deformable Part Model）**是 HOG+SVM 思路的进一步发展，也是深度学习检测器（尤其是 R-CNN 系列）出现之前最强的传统目标检测框架之一。它的核心思想是把一个物体表示成"一个粗粒度整体模板 + 若干个细粒度部件模板"的组合，部件之间允许一定范围的相对位置形变（比如人体检测里，头、躯干、四肢作为独立部件，彼此之间的相对位置可以在一定范围内浮动），通过隐变量 SVM（Latent SVM）联合优化整体与部件的匹配得分。

DPM 在 2008-2012 年间是 PASCAL VOC 目标检测竞赛的常胜框架，它对"部件-整体"关系的建模思路，也直接启发了后来 R-CNN 系列论文里"候选区域+特征提取+分类"这一范式的设计——某种程度上，DPM 可以被看作是深度学习检测器的重要精神先驱，虽然现在已经很少有人在生产环境里直接用它了。

> 思想借鉴意义 > 代码实践意义

## 八、特征匹配与图像配准

有了第四章讲的特征描述子之后，下一步自然是要解决"如何把两张图里对应的点对应起来"这个问题。这套技术是全景拼接、图像对齐、增强现实的底层基础。

### 8.1 特征匹配

```python
sift = cv2.SIFT_create()
kp1, des1 = sift.detectAndCompute(img1, None)
kp2, des2 = sift.detectAndCompute(img2, None)

# 暴力匹配
bf = cv2.BFMatcher()
matches = bf.knnMatch(des1, des2, k=2)

# Lowe's ratio test 筛掉不可靠匹配
good = [m for m, n in matches if m.distance < 0.75 * n.distance]

# FLANN 匹配器，大规模特征点场景下比 BFMatcher 快得多
index_params = dict(algorithm=1, trees=5)
search_params = dict(checks=50)
flann = cv2.FlannBasedMatcher(index_params, search_params)
```

Lowe's ratio test 是个非常重要但容易被忽视的细节——它通过比较"最近邻"和"次近邻"距离的比值来判断这个匹配是否可靠，能有效过滤掉大量歧义匹配，是 SIFT 论文里的原始设计，几乎所有基于描述子的匹配流程都应该带上这一步。

### 8.2 单应性矩阵与 RANSAC

得到匹配点对之后，如果两张图之间是纯粹的平面透视关系（比如拍同一面墙、同一张纸），可以求解单应性矩阵：

```python
src_pts = np.float32([kp1[m.queryIdx].pt for m in good]).reshape(-1, 1, 2)
dst_pts = np.float32([kp2[m.trainIdx].pt for m in good]).reshape(-1, 1, 2)

H, mask = cv2.findHomography(src_pts, dst_pts, cv2.RANSAC, ransacReprojThreshold=5.0)
```

这里必须提一下 **RANSAC（随机抽样一致性）**，它可以说是传统 CV 里最重要的"鲁棒估计"思想之一——通过反复随机采样最小子集拟合模型、统计内点数量，最终选出内点最多的模型，从而对抗匹配结果中大量存在的误匹配（外点）。这个思想不仅用在图像配准里，在三维重建、直线拟合、相机位姿估计中也无处不在，可以说是理解传统 CV"鲁棒性设计"绕不开的一课。

> 补充：如果你使用的是较新版本的 OpenCV，可以留意其 **USAC（Universal Sample Consensus）** 统一框架（例如 MAGSAC++ 等变体）。在外点比例更高、匹配更“脏”的情况下，USAC 家族往往比传统 RANSAC 更稳健。
>
> 由于不同 OpenCV 版本在枚举名/接口参数上略有差异，这里不强行给出固定代码，建议以本机 `cv2.getBuildInformation()` 对应版本的官方文档为准。


### 8.3 图像拼接

有了单应性矩阵，剩下的事情就是把图像 warp 到统一坐标系再融合：

```python
result = cv2.warpPerspective(img1, H, (width, height))
# 之后通常还需要做羽化融合（feather blending）避免拼接缝可见
```

OpenCV 也提供了封装好的高级 API `cv2.Stitcher_create()`，内部已经把特征提取、匹配、单应性估计、曝光补偿、多频段融合这一整套流程封装好了，适合快速实现全景拼接功能，不需要自己手搓每一步。

### 8.4 模板/形状配准的另一条路：ICP

如果处理的不是二维图像特征点，而是点云或轮廓点集的配准问题，**ICP（迭代最近点算法）** 是更常用的工具（OpenCV 的 `ximgproc` 或结合 Open3D 使用），核心思路是迭代地寻找最近点对应关系、求解刚体变换、更新点集，直到收敛。这个在三维视觉、机器人抓取姿态估计里经常出现。

## 九、运动检测、光流与目标跟踪

跟踪问题要解决的是"同一个目标在连续帧之间如何保持身份一致性"，这在视频分析、机器人导航里是核心能力，但在讲"跟踪"之前，先得解决更基础的"运动检测"问题。

### 9.1 帧差法与背景建模

固定机位场景下，背景通常是不变的，运动物体会导致像素值发生变化，最朴素的做法就是直接比较相邻帧：

```python
diff = cv2.absdiff(frame1, frame2)
_, motion_mask = cv2.threshold(diff, 25, 255, cv2.THRESH_BINARY)
```

**帧差法**实现简单、计算量极小，缺点也很明显——对光照突变敏感、容易产生"空洞"（运动物体内部颜色均匀的区域帧间差异很小，导致检测出的运动区域只有边缘轮廓是完整的），因此更适合作为快速原型验证，工程上通常会升级为**背景建模（Background Subtraction）**：

```python
back_sub = cv2.createBackgroundSubtractorMOG2(detectShadows=True)
# 或 cv2.createBackgroundSubtractorKNN()
fg_mask = back_sub.apply(frame)
```

MOG2（高斯混合模型）和 KNN 背景减除算法会持续用多帧数据动态更新一个"背景模型"（对每个像素维护一个概率分布，判断当前值是否符合历史背景分布），比单纯帧差法更能应对光照缓慢变化、背景中有轻微晃动（比如树叶摆动）的场景，是监控入侵检测、人流车流统计类应用的标准起点。

### 9.2 光流估计

光流描述的是图像中像素点随时间的运动矢量场，基本假设是"灰度不变性"——同一物点在相邻帧上亮度保持不变。

- **稀疏光流（Lucas-Kanade）**：只跟踪一小部分关键点（通常配合 `cv2.goodFeaturesToTrack` 先选点），计算量小，适合实时跟踪少量特征点。

```python
p1, status, err = cv2.calcOpticalFlowPyrLK(prev_gray, curr_gray, p0, None)
```

- **稠密光流（Farneback / DIS）**：计算图像每一个像素的运动矢量，能得到完整的运动场，但计算量大得多，适合运动分析、视频插帧、异常行为检测。

```python
flow = cv2.calcOpticalFlowFarneback(prev_gray, curr_gray, None,
                                      0.5, 3, 15, 3, 5, 1.2, 0)
```

### 9.3 传统目标跟踪算法

OpenCV 的 `legacy` 模块（旧版本在 `cv2.Tracker*_create()`）集成了一批经典跟踪算法：

| 算法 | 特点 |
|---|---|
| MeanShift / CamShift | 基于颜色直方图的密度峰值跟踪，CamShift 能自适应调整窗口大小 |
| KCF（核相关滤波） | 速度快，利用循环矩阵和 FFT 加速，是相当长一段时间内的"性价比之王" |
| CSRT | 精度比 KCF 更高，速度稍慢，适合对精度要求更高的场景 |
| MOSSE | 极致轻量，适合算力极受限的嵌入式设备 |

```python
tracker = cv2.TrackerCSRT_create()
tracker.init(frame, bbox)
success, bbox = tracker.update(new_frame)
```

### 9.4 卡尔曼滤波：跟踪任务里的"隐藏功臣"

卡尔曼滤波本身不是一个"检测"或"跟踪"算法，而是一个**状态估计与预测**的数学工具，但它几乎是所有跟踪系统（包括很多深度学习检测器 + 跟踪器的组合系统，如 DeepSORT）背后不可或缺的一环——用于在检测丢失的帧里做轨迹预测、平滑跟踪抖动、关联多目标身份。

```python
kf = cv2.KalmanFilter(4, 2)  # 状态维度4（x,y,vx,vy），观测维度2（x,y）
kf.transitionMatrix = np.array([[1,0,1,0],[0,1,0,1],[0,0,1,0],[0,0,0,1]], np.float32)
kf.measurementMatrix = np.array([[1,0,0,0],[0,1,0,0]], np.float32)

prediction = kf.predict()
kf.correct(np.array([[measured_x],[measured_y]], np.float32))
```

传统检测 + 卡尔曼滤波 + 匈牙利算法（数据关联）这套组合，其实就是 **SORT 算法**的核心逻辑——理解了这个组合，再去看 DeepSORT 用深度特征替换外观匹配部分，会觉得整个脉络非常清晰。

## 十、相机模型与三维视觉

这一部分涉及从二维图像"反推"三维世界信息，是机器人、AR/VR、工业测量的核心技术栈。

### 10.1 相机标定

任何精确的尺寸测量、坐标映射、三维重建任务，第一步都是相机标定——求解相机的内参矩阵（焦距、主点）和畸变系数。OpenCV 的 `cv2.calibrateCamera` 实现的正是**张正友标定法**（Zhang's Method）：只需要用相机在不同角度拍摄若干张棋盘格标定板照片，就能同时求解出内参矩阵和每张图对应的外参（旋转+平移），不需要昂贵的专用标定设备，是目前工业界和学术界最主流的相机标定方案。

具体的角点检测、亚像素细化、`calibrateCamera` 调用流程，在「[3.4.6 相机标定与去畸变实现](#346-相机标定与去畸变实现)」已经完整给出，这里不再重复，只强调标定结果在三维视觉里的两层意义：

```python
ret, mtx, dist, rvecs, tvecs = cv2.calibrateCamera(objpoints, imgpoints, gray.shape[::-1], None, None)
```

- **内参矩阵 + 畸变系数**：是第三章讲的"去畸变"这一预处理步骤的直接输入，工业视觉里"像素坐标 → 物理坐标"的转换必须建立在准确标定的基础上，这一步没做好，后面所有的尺寸测量都是空中楼阁。
- **每张标定图对应的外参（rvecs、tvecs）**：则是本章后面 PnP 位姿估计（见 [10.3](#103-pnp-位姿估计)）、双目立体视觉（见 [10.2](#102-立体视觉与深度估计)）的基础——本质上标定这一步求解的就是"相机坐标系"和"世界坐标系"之间的对应关系，三维视觉的后续所有计算都建立在这套对应关系之上。

### 10.2 立体视觉与深度估计

- **双目标定**（`cv2.stereoCalibrate`）：求解两个相机之间的相对位姿关系。
- **立体校正**（`cv2.stereoRectify`）：把左右图像校正到同一水平线上，简化后续匹配搜索为一维问题。
- **视差计算**（`cv2.StereoBM` / `cv2.StereoSGBM`）：在校正后的图像上逐行搜索匹配点，计算视差图，再通过三角测量原理换算成深度信息。

```python
stereo = cv2.StereoSGBM_create(numDisparities=64, blockSize=9)
disparity = stereo.compute(left_gray, right_gray)
```

双目视觉是传统 CV 里少数能够"无需深度学习"就获得稠密深度信息的方法，在没有激光雷达/结构光传感器的场景下，依然是低成本三维感知的重要选择。

### 10.3 PnP 位姿估计

已知物体在三维空间中的若干个点坐标，以及它们在图像上的二维投影，可以反解出相机相对物体的位姿（旋转+平移）：

```python
success, rvec, tvec = cv2.solvePnP(object_points, image_points, camera_matrix, dist_coeffs)
```

这个在增强现实（虚拟物体贴合真实场景）、机器人抓取（确定目标物体的空间姿态）里是核心算法之一。

### 10.4 SfM 与 SLAM 的传统基础

虽然现代 SLAM 系统（如 ORB-SLAM）已经是相当复杂的工程系统，但它的前端特征提取与匹配（第四、八章讲的 ORB 特征）、后端位姿优化，底层都还是建立在传统 CV 的几何视觉基础之上——这也是为什么"传统 CV 基本功"对做机器人视觉、AR 的工程师依然是必修课。

## 十一、频域、形态学与图像复原的"奇技淫巧"

这一章讲三类经常被当作"配菜"，但实际上解决问题极其高效的工具。

### 11.1 形态学操作

基于集合论的图像处理方法，核心操作是**腐蚀**和**膨胀**，二者的各种组合能解决大量结构化的图像清理问题：

```python
kernel = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (5,5))

erosion = cv2.erode(binary, kernel)                              # 腐蚀：缩小前景，断开细小连接
dilation = cv2.dilate(binary, kernel)                             # 膨胀：扩大前景，填补小孔洞
opening = cv2.morphologyEx(binary, cv2.MORPH_OPEN, kernel)        # 开运算 = 先腐蚀后膨胀，去小噪点
closing = cv2.morphologyEx(binary, cv2.MORPH_CLOSE, kernel)       # 闭运算 = 先膨胀后腐蚀，填补小孔洞
gradient = cv2.morphologyEx(binary, cv2.MORPH_GRADIENT, kernel)   # 形态学梯度，提取边界
tophat = cv2.morphologyEx(gray, cv2.MORPH_TOPHAT, kernel)         # 顶帽，提取比背景亮的小区域
blackhat = cv2.morphologyEx(gray, cv2.MORPH_BLACKHAT, kernel)     # 黑帽，提取比背景暗的小区域
```

形态学操作看似简单，但在**二值图像后处理**环节几乎无处不在——开运算去除分割结果中的椒盐噪点、闭运算填补目标内部的小孔洞，几乎是任何分割/阈值流程后面都会跟上的标准动作。顶帽/黑帽变换在光照不均匀背景下提取小尺寸缺陷（比如金属表面的小划痕、PCB 上的小污渍）特别好用，因为它本质上是在做"局部背景消除"。

还有一个相对小众但很有意思的操作叫**击中击不中变换（Hit-or-Miss Transform）**（`cv2.morphologyEx(binary, cv2.MORPH_HITMISS, kernel)`），它同时使用一对结构元素（前景匹配核 + 背景匹配核），只有当邻域"精确匹配"这个模式时才保留该像素，因此特别适合做**精确形状定位**——比如在二值图像里找特定朝向的 T 形接头、十字交叉点，或者从骨架图中提取端点和分叉点，是形态学工具箱里"最挑剔"但也最精准的一个操作。

### 11.2 距离变换

`cv2.distanceTransform` 计算二值图像中每个前景像素到最近背景像素的距离，用途非常广：

- 前面讲的分水岭分割里用来找"确定前景"的种子点
- 骨架提取（细化）的基础
- 计算物体的"内切圆半径"，用于形状分析

### 11.3 图像金字塔

`cv2.pyrDown` / `cv2.pyrUp` 构建高斯金字塔，用于多尺度分析；拉普拉斯金字塔（相邻两层高斯金字塔的差）常用于图像融合（比如无缝拼接两张不同曝光的图像）和图像压缩编码的基础结构。

### 11.4 图像复原：当退化过程"已知"的时候

前面讲的去噪（包括第四章 4.5.1 节提到的频域陷波滤波），本质上都是在"不需要精确知道退化的数学模型"的前提下做通用净化处理。但还有一类更精细的问题——如果我们对图像的**退化过程本身有数学建模**（比如已知运动模糊的方向和幅度、已知光学系统的点扩散函数），就可以尝试"反向求解"，把图像尽可能恢复到退化前的状态，这就是**图像复原（Image Restoration）**要解决的问题，和前面泛化去噪的思路不同，它更像是解一个逆问题。

- **逆滤波（Inverse Filtering）**：如果退化过程可以用一个已知的退化函数 $H(u,v)$ 在频域表示（$G = H \cdot F + N$），最直接的想法是在频域直接除以 $H(u,v)$ 求出原图估计。但这个方法对噪声极其敏感——一旦 $H(u,v)$ 在某些频率上接近零，噪声会被放大到不可用的程度，因此纯逆滤波在实际工程里很少直接用，更多是作为理解后续算法的理论起点。

- **维纳滤波（Wiener Filtering）**：在逆滤波的基础上引入了噪声与信号功率谱比值的修正项，本质上是在"完全去噪"和"完全保留细节"之间找一个统计意义上的最优折中，公认是退化模型已知场景下最经典的复原方法。

```python
# 频域维纳滤波简化实现思路
def wiener_filter(img, kernel, K=0.01):
    kernel /= np.sum(kernel)
    dummy = np.copy(img)
    dummy = np.fft.fft2(dummy)
    kernel_fft = np.fft.fft2(kernel, s=img.shape)
    kernel_fft = np.conj(kernel_fft) / (np.abs(kernel_fft)**2 + K)
    dummy = dummy * kernel_fft
    return np.abs(np.fft.ifft2(dummy))
```

- **运动模糊反卷积**：相机或物体在曝光时间内发生相对运动会产生方向性的模糊，如果能估计出运动的方向和位移长度，就可以构造出对应的运动模糊核，再用维纳滤波或 Richardson-Lucy 反卷积算法（`scipy` / `skimage` 中有现成实现）去估计清晰图像，工业高速产线的运动拖影校正、老照片修复都会用到这个思路。

- **约束最小二乘复原**：在维纳滤波"知道噪声功率谱"这个较强假设不成立时的替代方案，通过引入一个平滑性约束项（通常是拉普拉斯算子），在"复原图像要尽量平滑"和"复原结果要尽量贴合观测图像"之间找平衡，是另一种经典的正则化复原思路。

这部分内容在通用工业质检场景里出场率不算最高（因为大部分质检场景的问题是"噪声/光照"而不是"系统性退化"），但在天文成像、显微镜像差校正、医学影像重建（比如 CT 的 FBP 滤波反投影重建算法，本质上也是一种频域复原思想的应用）里，是绕不开的核心技术。

## 十二、Video 模块：视频输入输出与采集

前面十一章讲的算法大多是"拿到一帧图像之后怎么处理"，这一章往前退一步，讲讲这些图像本身是怎么进来、处理完又怎么出去的——也就是 OpenCV 的 `videoio` 相关能力，工程上通常统称为 Video 模块。

### 12.1 VideoCapture：读取摄像头与视频文件

```python
cap = cv2.VideoCapture(0)              # 0 表示第一个本地摄像头
# cap = cv2.VideoCapture('input.mp4')  # 也可以直接传视频文件路径
# cap = cv2.VideoCapture('rtsp://user:pass@ip:port/stream')  # 网络摄像头/RTSP流

if not cap.isOpened():
    raise IOError("无法打开视频源")

while True:
    ret, frame = cap.read()   # ret 表示是否成功读到帧，frame 是图像数据（读到文件末尾 ret 会变 False）
    if not ret:
        break
    # 这里插入你想做的图像处理逻辑
    cv2.imshow('frame', frame)
    if cv2.waitKey(1) & 0xFF == ord('q'):
        break

cap.release()
cv2.destroyAllWindows()
```

`VideoCapture` 统一封装了本地摄像头、视频文件、网络流（RTSP/RTMP/HTTP）三种输入源，区别只在于构造函数传入的参数不同——这一点对工业相机场景也同样适用：很多工业相机（如海康、大恒）会提供自己的 SDK，但只要相机支持标准 USB/GigE Vision 协议或者暴露了 V4L2 接口，也能被 `VideoCapture` 直接识别。

### 12.2 Camera Property：读写摄像头参数

```python
cap.set(cv2.CAP_PROP_FRAME_WIDTH, 1920)
cap.set(cv2.CAP_PROP_FRAME_HEIGHT, 1080)
cap.set(cv2.CAP_PROP_FPS, 30)
cap.set(cv2.CAP_PROP_EXPOSURE, -6)     # 部分工业/USB相机支持手动曝光，取值范围因驱动而异

width  = cap.get(cv2.CAP_PROP_FRAME_WIDTH)
height = cap.get(cv2.CAP_PROP_FRAME_HEIGHT)
fps    = cap.get(cv2.CAP_PROP_FPS)
```

这里有个工程上常踩的坑：**`cap.set()` 的返回值需要检查**，不是所有摄像头驱动都支持修改所有属性，很多消费级 USB 摄像头对分辨率/帧率的支持是离散档位而非连续可调，设置一个不支持的值往往会静默失败并回退到默认值，工业项目里建议设置后立刻用 `cap.get()` 读回来确认是否生效。

### 12.3 VideoWriter：写出视频文件

```python
fourcc = cv2.VideoWriter_fourcc(*'mp4v')   # 编码格式，常见还有 'XVID'、'avc1'
out = cv2.VideoWriter('output.mp4', fourcc, fps=30, frameSize=(1920, 1080))

while True:
    ret, frame = cap.read()
    if not ret:
        break
    out.write(frame)

out.release()
```

`frameSize` 必须和实际写入帧的尺寸完全一致，否则会写出损坏或无法播放的视频文件——这是新手在做"处理后视频另存"这类需求时最常见的坑，尤其是当处理流程里做了裁剪或缩放却忘记同步修改 `frameSize` 参数。

### 12.4 工程实践要点

- **多线程读帧**：`cap.read()` 是阻塞调用，在需要同时处理多路摄像头，或者处理速度跟不上采集帧率时，通常会开一个独立线程专门负责 `read()`，用队列（`queue.Queue`，一般只保留最新一帧）解耦"采集"和"处理"两个环节，避免处理慢拖慢采集导致的花屏或延迟累积。
- **丢帧策略**：如果处理速度跟不上摄像头帧率，与其让队列越堆越多（导致处理的永远是"过去"的画面），不如设计成"只保留最新帧、旧帧直接丢弃"的策略，这在实时监控、机器人视觉这类对时延敏感的场景里是常见设计。
- **RTSP 流的稳定性**：网络摄像头场景下 `VideoCapture` 读流经常会遇到断流、花屏，工程上通常需要加上自动重连逻辑（检测到 `ret=False` 连续多次后重新 `cap.open()`），单纯依赖 OpenCV 默认行为在生产环境里往往不够稳健。
- **与第九章的衔接**：本章讲的是"怎么拿到帧"，拿到帧之后要做背景建模、光流、跟踪，就是第九章"运动检测、光流与目标跟踪"覆盖的内容——Video 模块和跟踪算法几乎总是配套出现。

## 十三、DNN 模块：用 OpenCV 跑深度学习推理

前面十二章讲的都是"不需要训练"的传统算法，但 OpenCV 本身也内置了一个轻量级的深度学习推理引擎——`dnn` 模块。它不负责训练，只负责**加载别的框架训练好的模型、做前向推理**，定位类似于一个"零依赖、跨平台的推理运行时"。

### 13.1 dnn 模块能做什么、不能做什么

`dnn` 模块可以直接加载以下几种主流框架导出的模型文件，不需要额外安装 TensorFlow/PyTorch 这类重量级框架：

| 来源框架 | 加载函数 | 常见文件格式 |
|---|---|---|
| ONNX（PyTorch/多数框架通用导出格式） | `cv2.dnn.readNetFromONNX()` | `.onnx` |
| TensorFlow | `cv2.dnn.readNetFromTensorflow()` | `.pb` |
| Caffe | `cv2.dnn.readNetFromCaffe()` | `.prototxt` + `.caffemodel` |
| Darknet（YOLOv3/v4 系官方实现） | `cv2.dnn.readNetFromDarknet()` | `.cfg` + `.weights` |

**能做的**：图像分类、目标检测、语义分割等前向推理任务，在 CPU 上通过 Intel 的 OpenVINO 后端加速，也能调用 CUDA 后端跑在 NVIDIA GPU 上（需要自行编译带 CUDA 支持的 OpenCV）。

**不能做的**：不支持训练、不支持反向传播，模型结构必须是导出时就固定好的（不支持动态图那种运行时可变的计算图逻辑），对一些较新的算子/层类型支持可能滞后于原生框架，遇到不支持的算子需要自己写自定义层或退回到原生框架推理。

### 13.2 blobFromImage：从图像到模型输入

深度学习模型的标准输入是一个四维张量（batch, channel, height, width），`cv2.dnn.blobFromImage` 就是负责把普通图像转换成这种格式的预处理函数：

```python
blob = cv2.dnn.blobFromImage(
    img,
    scalefactor=1/255.0,        # 归一化系数，把 0-255 缩放到 0-1
    size=(640, 640),            # 模型要求的输入尺寸
    mean=(0, 0, 0),             # 均值中心化（部分模型需要减去训练时的通道均值）
    swapRB=True,                # OpenCV 默认 BGR，大多数模型训练时用 RGB，这里需要交换
    crop=False
)
net.setInput(blob)
output = net.forward()
```

这一步几乎是所有 `dnn` 推理流程的固定起手式，实际项目中最容易出问题的地方也恰好在这里——**`scalefactor`、`mean`、`swapRB` 这几个参数必须和模型训练时的预处理完全对齐**，任何一个参数配错，模型都不会报错，只会输出看起来"合理但错误"的结果，这也是 `dnn` 模块调试里最隐蔽的一类 bug。

### 13.3 NMS：检测后处理的老朋友

目标检测模型输出的原始候选框通常存在大量重叠，`dnn` 模块内置了非极大值抑制函数来做后处理：

```python
indices = cv2.dnn.NMSBoxes(boxes, confidences, score_threshold=0.5, nms_threshold=0.4)
```

这里正好和第七章、第十六章反复提到的 NMS 呼应——不管是传统检测流水线还是深度学习检测器，NMS 这一步基本是绕不开的"胶水算法"，`cv2.dnn.NMSBoxes` 只是把这个经典几何算法直接内置到了 dnn 模块里，省去自己实现的功夫。

### 13.4 工程实践建议

- **模型格式优先选 ONNX**：ONNX 是目前跨框架兼容性最好的格式，PyTorch 导出的模型经过 `torch.onnx.export` 之后，绝大多数情况下都能被 `dnn` 模块直接加载，比 TensorFlow/Caffe 路线的坑更少。
- **YOLO 系列模型的部署**：YOLOv5/v8 官方都提供了导出 ONNX 的脚本，导出后可以直接用 `dnn` 模块做推理，不需要安装 PyTorch，这在很多"只需要部署、不需要重新训练"的边缘设备场景里能大幅减小部署包体积——第十六章 16.7 节提到的钻石检测场景，实际落地时如果对依赖体积敏感，也是一个可以考虑的路线。
- **性能不如原生框架 + GPU**：`dnn` 模块的优势是部署简单、依赖少，而不是极致性能，如果对推理速度有极高要求（比如大批量、高帧率场景），原生 PyTorch/TensorRT 通常还是更快的选择，`dnn` 模块更适合"轻量部署、少依赖"这类场景。
- **和传统 CV 后处理的结合**：`dnn` 模块只负责模型前向推理这一步，前面章节讲的 ROI 裁剪、几何校正、连通域分析、坐标映射，在实际的深度学习视觉系统里依然是必不可少的"胶水层"——这也正是第十七章要讨论的传统 CV 与深度学习分工问题。

## 十五、GUI 模块：窗口、交互与和 PyQt6 的取舍

前面十四章讲的都是"算法怎么算"，这一章讲讲结果"怎么看、怎么点"——也就是 OpenCV 自带的高层 GUI 模块 `highgui`。这块内容工程上很基础，但对做过 PyQt6 桌面应用开发的读者（比如前文提到的实验室原料管理系统、PDF 处理桌面应用）来说，理解 OpenCV GUI 的能力边界，能帮你更快判断一个需求到底该用 `cv2.imshow` 糊一个调试窗口，还是该正儿八经上 PyQt6。

### 15.1 窗口管理基础 API

```python
cv2.namedWindow('demo', cv2.WINDOW_NORMAL)   # 创建可调整大小的窗口（默认 WINDOW_AUTOSIZE 不可拖拽缩放）
cv2.imshow('demo', img)                      # 在窗口中显示图像
key = cv2.waitKey(0)                         # 阻塞等待按键，0表示无限等待；传入毫秒数则是非阻塞轮询
cv2.destroyWindow('demo')                    # 关闭指定窗口
cv2.destroyAllWindows()                      # 关闭所有窗口
cv2.resizeWindow('demo', 800, 600)           # 调整窗口大小
cv2.moveWindow('demo', 100, 100)             # 移动窗口位置
```

`cv2.waitKey()` 是个经常被低估的函数——它不仅负责等待按键，还承担着**驱动窗口消息循环**的职责（Windows/X11 的事件处理本质上需要这个调用来"泵"消息），如果一个 `cv2.imshow` 之后完全不调用 `waitKey`，窗口大概率会卡死或者根本不刷新，这是新手写调试脚本时最常踩的坑之一。

### 15.2 滑动条（Trackbar）：轻量级参数调试神器

```python
def on_change(val):
    pass  # 回调函数，val 是滑动条当前值

cv2.namedWindow('调参窗口')
cv2.createTrackbar('阈值', '调参窗口', 127, 255, on_change)

while True:
    threshold_val = cv2.getTrackbarPos('阈值', '调参窗口')
    _, binary = cv2.threshold(gray, threshold_val, 255, cv2.THRESH_BINARY)
    cv2.imshow('调参窗口', binary)
    if cv2.waitKey(1) == 27:  # ESC 退出
        break
```

这是 OpenCV GUI 里性价比最高的一个功能——不需要写任何界面代码，几行 `createTrackbar` 就能拉出一个"实时调参"面板，本文前面反复提到的"Canny 双阈值""CLAHE 的 clipLimit""HoughCircles 的半径范围"这类需要反复试参数的场景，配合 Trackbar 调试效率极高，比每次改代码重跑快得多。

### 15.3 鼠标交互与绘图 API

```python
def on_mouse(event, x, y, flags, param):
    if event == cv2.EVENT_LBUTTONDOWN:
        print(f"点击坐标: ({x}, {y})")
    elif event == cv2.EVENT_MOUSEMOVE and flags == cv2.EVENT_FLAG_LBUTTON:
        cv2.circle(img, (x, y), 3, (0, 255, 0), -1)  # 按住左键拖动画圆

cv2.namedWindow('draw')
cv2.setMouseCallback('draw', on_mouse)
```

配合基础绘图 API（`cv2.rectangle`、`cv2.circle`、`cv2.line`、`cv2.putText`），能快速搭出一个"框选 ROI""标注关键点"这类简易交互工具——第十六章 16.9 节提到的 GrabCut 交互式分割，实际使用时通常就是靠这套鼠标回调机制让用户画初始矩形框。

### 15.4 OpenCV GUI 相比 PyQt6 的局限性

`highgui` 的定位从始至终都是"给开发者调试算法用的最小可用窗口系统"，不是用来做产品级桌面应用的。把它和 PyQt6 放在一起对比，差距是全方位的：

| 维度 | OpenCV GUI（highgui） | PyQt6 |
|---|---|---|
| 控件丰富度 | 只有窗口、Trackbar、鼠标回调，没有按钮、下拉框、表格、对话框等标准控件 | 完整的控件库（QPushButton、QComboBox、QTableWidget、QFileDialog 等），能搭建任意复杂度的界面 |
| 布局系统 | 无布局概念，控件位置基本靠硬编码坐标 | 完整的布局管理器（QVBoxLayout/QGridLayout 等），支持响应式调整 |
| 样式与美观度 | 界面风格陈旧、不可定制，无法做出现代化 UI | 支持 QSS 样式表，能做出媲美原生应用的现代界面 |
| 事件驱动模型 | 简化的回调机制，复杂交互逻辑容易写成"面条代码" | 完整的信号槽（Signal/Slot）机制，适合复杂状态管理 |
| 多窗口/多线程协作 | 主线程强依赖，`waitKey` 阻塞式设计，多窗口协调复杂 | 原生支持多窗口、对话框、模态窗口，配合 QThread 做异步任务是标准范式 |
| 硬件外设集成 | 无原生支持，需要自己接入串口/HID库（如前文提到的 Modbus 电子秤、USB HID 扫码枪场景） | 可以整合 `pyserial`、`hidapi` 等第三方库，构建完整的业务表单+外设交互流程 |
| 打包分发 | 一般作为脚本或算法调试工具，不考虑独立分发 | 配合 PyInstaller 可打包为独立可执行文件，适合分发给非技术用户 |
| 数据库/业务逻辑集成 | 无相关能力，需要自己在主循环里手写 | 天然适合与 SQLite/PostgreSQL、ORM、业务状态机结合，构建完整桌面应用 |

一句话总结这个边界：**`cv2.imshow` + Trackbar 这套组合，适合"验证一个算法效果、调一组参数"这种开发阶段的临时性需求；一旦涉及到需要给非技术用户使用的正式产品（登录界面、数据录入表单、报表导出、打印标签），就必须上 PyQt6 这类成熟的 GUI 框架**。

实际项目里一个很自然的分工是：算法原型阶段用 `cv2.imshow` + Trackbar 快速验证参数、锁定算法方案；进入产品化阶段后，把验证好的算法逻辑封装成纯函数，接入到 PyQt6 搭建的正式界面里，图像处理结果通过 `QImage`/`QPixmap` 显示在 `QLabel` 或自定义 `QWidget` 上——这也是前文提到的 PyQt6 桌面应用项目（实验室原料管理系统的电子秤读数可视化、PDF 处理工具的预览界面）实际采用的路线，OpenCV 只负责"算得对"，PyQt6 负责"看得好、用得顺"。

## 十六、算法组合范式：常见任务的完整流水线

好，前面十五章基本上是把"武器库"梳理了一遍，这一章才是真正的重头戏——**单个算法很少能独立解决实际问题，真正的工程能力体现在怎么把它们串成一条能打的流水线**。下面按任务类型列举几个最常见、也最值得掌握的组合范式。

顺带说一句，工业视觉圈子里除了 OpenCV，另一个绕不开的名字是商业机器视觉库 **HALCON**（MVTec 出品）——它提供的 `find_shape_model`（基于边缘/形状的模板匹配）、`binary_threshold`、Blob 分析等算子，本质上和本文讲的这套传统算法体系是同一套理论基础，只是 HALCON 做了大量工业级的工程优化（比如亚像素精度、旋转缩放不敏感的形状匹配）和商业化封装，很多产线项目会用 HALCON 做核心算法、OpenCV 做外围图像 I/O 和辅助处理，两者并不冲突，理解了 OpenCV 这套体系，迁移到 HALCON 的算子逻辑上手会很快。

### 16.1 任务一：工业表面缺陷检测（划痕/污渍/裂纹）

```
图像采集 → 灰度化 → CLAHE对比度增强 → 高斯/中值滤波去噪
        → 顶帽/黑帽变换突出局部异常 → Otsu/自适应阈值二值化
        → 形态学开运算去噪点 → 连通域分析/轮廓提取
        → 按面积、长宽比、圆度过滤误检 → 输出缺陷坐标与分类
```

这条流水线的关键在于**顶帽/黑帽变换**这一步——它相当于先用一个大尺寸结构元素估计出"背景亮度分布"，再从原图中减掉，从而把局部的小尺寸异常（缺陷通常远小于整个物体）凸显出来，之后再做阈值分割就容易得多。这是工业质检里最经典、也最常被低估的一招。

### 16.2 任务二：粘连颗粒/细胞计数

```
图像采集 → 灰度化 → 高斯滤波 → Otsu二值化
        → 形态学开运算去噪 → 距离变换找到"确定前景"种子点
        → 连通域标记 → 分水岭算法分离粘连区域
        → 统计连通域数量 → 输出计数结果
```

这就是第六章 6.5 节讲过的组合，值得再强调一次它的普适性——只要是"目标物体大致呈团块状、且经常粘连在一起"的计数任务，这套流程基本都能直接套用。

### 16.3 任务三：文档/卡证矫正与信息提取（OCR 前处理）

```
图像采集 → 灰度化 → 高斯滤波去噪 → Canny边缘检测
        → 轮廓提取 → 多边形近似(approxPolyDP)找四边形轮廓
        → 透视变换矫正为正视图 → 自适应阈值二值化
        → （交给OCR引擎，如Tesseract）
```

这条流水线的巧妙之处在于**用几何轮廓分析代替深度学习检测**来定位文档边界——因为文档边界通常是最强的直线特征，Canny + 轮廓 + 多边形近似这套组合几乎是"零训练成本"地解决了文档定位问题，只有在背景极其复杂、边界不清晰的情况下才需要上深度学习方案。

### 16.4 任务四：全景图像拼接

```
多张图像采集(有重叠区域) → SIFT/ORB特征提取 → FLANN/BF特征匹配
        → Lowe's ratio test筛选优质匹配 → RANSAC求解单应性矩阵
        → 透视变换对齐 → 多频段融合去除拼接缝 → 输出全景图
```

第八章讲过的每一步在这里都用上了，这也是为什么很多教材把图像拼接作为"传统 CV 综合应用"的压轴案例——它几乎覆盖了特征提取、匹配、鲁棒估计、几何变换的完整链条。

### 16.5 任务五：视频运动目标检测与跟踪

```
视频流输入 → 背景建模(MOG2/KNN背景减除) → 形态学开闭运算去噪
        → 连通域/轮廓提取候选目标框 → 卡尔曼滤波预测轨迹
        → 匈牙利算法做帧间目标关联(数据关联) → 输出带ID的运动轨迹
```

```python
back_sub = cv2.createBackgroundSubtractorMOG2(detectShadows=True)
fg_mask = back_sub.apply(frame)
```

这套流程本质上就是前文提到的 SORT 跟踪算法的骨架，在固定机位监控场景（比如统计通过某个区域的人流/车流）里，比直接上深度学习检测器+跟踪器要轻量得多，且不需要任何训练数据。

### 16.6 任务六：条码/二维码定位与识别

```
图像采集 → 灰度化 → Sobel梯度计算(区分条码区域高频纹理与背景)
        → 形态学闭运算连接条纹 → 轮廓提取找到最大连通区域
        → 透视矫正 → 交给专用解码库(pyzbar/ZXing)
```

条码定位是一个很好的例子，说明**传统 CV 的梯度/纹理特征在结构化、规则图案检测中，往往比通用深度学习检测器更快、更省资源**，这也是为什么条码扫描 SDK 里传统方法依然是主流方案。

### 16.7 任务七：Chaojian 场景相关——高分辨率大图的多子块目标检测后处理

结合前面聊到的钻石检测这类"大图切块 + 深度学习推理 + 传统后处理"场景，传统 CV 在这里承担的角色其实非常关键，即便主检测模型是 YOLOv8：

```
大图(如5120x5120)切分为网格子图 → 各子图独立YOLOv8推理得到候选框
        → 子图内部去重(基于中心距离或IoU的NMS)
        → 跨子图边界目标合并(基于重叠区域的框合并策略)
        → 全局坐标映射(子图局部坐标→原图全局坐标)
        → 二次NMS消除跨边界重复检测
        → 调试可视化(按置信度分级着色、标注框尺寸)
```

这里能看到一个很有意思的现象——**深度学习负责"识别"，传统 CV 负责"组织与清理"**。NMS 本身就是一个纯粹的传统几何算法（基于 IoU 或中心距离的贪心去重），边界合并依赖的是连通域/重叠面积计算这类经典几何操作，坐标映射是纯仿射变换，可视化调试用的是 OpenCV 最基础的绘图 API。可以说，越是工程化、大规模的深度学习视觉系统，传统 CV 在"胶水层"里的存在感反而越强。

### 16.8 任务八：织物/金属表面纹理异常检测（小样本场景）

前面第 16.1 节讲的是"划痕、污渍"这类局部明显异常的检测，但还有一类更难的场景——异常并不表现为局部的亮/暗斑块，而是**整体纹理规律被打破**（比如织物的经纬纹理是否均匀、金属拉丝纹理是否一致），这种情况下逐像素阈值分割往往不奏效，更常见的套路是"分块统计 + 距离度量"：

```
Bilateral/NL-means去噪 → SLIC超像素分块(或简单滑窗分块)
        → 每个块提取LBP纹理直方图/灰度统计特征
        → 计算每块特征与"正常样本模板"的马氏距离(Mahalanobis Distance)
        → 距离超过阈值的块标记为异常 → 形态学聚合异常块输出报警区域
```

这套流程有个很实际的优势——**样本需求极低**。只需要收集一批"合格品"图像统计出正常纹理特征的均值和协方差（构建马氏距离所需的统计模型），完全不需要标注"缺陷长什么样"，这一点在缺陷样本天然稀少（次品率往往只有百分之一甚至更低）的产线上，比需要大量标注缺陷样本的深度学习方案实用得多，是很多"小样本/零样本"工业异常检测项目的第一选择 baseline。

### 16.9 任务九：医学 X 光虚拟双能减影

医学影像领域有一个非常经典、也很有代表性的传统算法组合——**虚拟双能减影（Virtual Dual-Energy Subtraction）**，用于胸部 X 光片中把骨骼结构和软组织（肺部）分离，帮助医生更清晰地观察容易被肋骨遮挡的肺部结节：

```
DR原始曝光图像 → 空气校正/散射校正(消除探测器本底噪声和X光散射)
        → 基于物质衰减系数差异的高低能对数域线性组合(虚拟双能减影核心步骤)
        → 分别得到"软组织增强图"与"骨骼增强图"
        → NL-means去噪(医学影像对细节保真度要求高，优先选非局部均值而非高斯)
        → SLIC超像素预分割 + 区域生长勾画可疑结节轮廓
        → 形态学开运算筛除血管断面等假阳性 → 输出可疑区域供医生复核
```

这套流程的关键点在于"虚拟"二字——传统双能减影需要两次不同能量的物理曝光，而虚拟双能减影只需要单次常规曝光，通过对数域的图像处理运算，利用骨骼和软组织对 X 光衰减系数的差异，"模拟"出双能减影的效果，患者不需要承受额外的辐射剂量。这个案例也很好地说明了传统 CV 在医疗这类对"可解释性、可追溯性"要求极高的领域里，依然是监管更容易接受、临床医生更信任的技术路线。

## 十七、传统 CV 与深度学习的分工与融合

聊到这里，其实已经能得出一个比较清晰的结论了：传统 CV 和深度学习并不是"谁取代谁"的竞争关系，而更像是**分工协作**的关系。粗略总结一下各自的优势边界：

| 维度 | 传统 CV 更有优势 | 深度学习更有优势 |
|---|---|---|
| 训练数据 | 不需要标注数据 | 需要大量标注数据 |
| 可解释性 | 每一步都可追踪、可调试 | 黑盒，调试困难 |
| 复杂语义理解 | 弱（无法理解"这是一只猫"这种语义） | 强 |
| 结构化、规则性强的任务 | 强（条码、文档边框、几何形状） | 一般（容易过拟合到规则性上） |
| 计算资源要求 | 低，适合嵌入式/边缘设备 | 高，通常需要 GPU |
| 复杂光照/姿态/遮挡场景 | 弱，容易失效 | 强，泛化能力好 |
| 精确几何测量 | 强（像素级精度、有明确数学模型） | 一般（除非专门设计） |
| 开发迭代速度 | 快（改个阈值就能验证） | 慢（改动往往需要重新训练） |

实际工程里更常见的做法，是把两者结合起来，形成"深度学习负责语义理解，传统 CV 负责精确定位与后处理"的混合流水线——第 16.7 节的大图检测案例就是个典型样本。类似的混合模式还包括：

- 深度学习做粗定位（比如检测出手机屏幕区域），传统 CV 做精细分割和缺陷定位（在屏幕区域内用阈值+形态学找划痕）
- 传统 CV 做数据增强的预处理（透视矫正、光照归一化），提升深度学习模型的训练数据质量
- 深度学习模型输出的候选框，用传统 NMS、卡尔曼滤波做后处理和跟踪平滑
- 传统特征匹配（ORB/SIFT）用于快速去重、图像检索的粗筛阶段，深度学习特征（如 CNN embedding）用于精细排序阶段

理解这种分工，比单纯争论"哪个更好"更有实际意义。

## 十八、工程实践中的性能与调优建议

最后聊几条比较实在的工程经验，这些东西教科书上不一定写，但踩过坑就知道有多重要。

1. **优先用 NumPy 向量化操作而不是 Python 循环**。OpenCV 的底层是 C++ 实现，但如果外面套了一层逐像素的 Python for 循环，性能会被拖得很惨，能用 OpenCV/NumPy 内置的批量操作就别自己写循环。

2. **ROI 裁剪永远优先于全图处理**。如果已知感兴趣区域的大致范围（比如传送带上固定的检测工位），先裁剪 ROI 再处理，能大幅减少计算量——这个原则听起来很基础，但实际项目里经常被忽略。

3. **多线程/多进程处理批量图像**。OpenCV 的很多函数本身默认会用多线程（依赖编译时是否启用 TBB/OpenMP），批量处理多张独立图像时，用 Python 的 `multiprocessing` 或 C++ 的线程池往往能有效提速，但要注意 OpenCV 内部线程与外部并行可能产生竞争，必要时用 `cv2.setNumThreads()` 做协调。

4. **阈值类参数不要硬编码，做成可配置项**。工业现场的光照条件会随时间漂移（镜头脏了、光源老化），把 Canny 阈值、二值化阈值这些参数暴露成配置文件里可调的项，比写死在代码里能省很多现场调试的麻烦。

5. **调试可视化不是可有可无的"锦上添花"**。像素级别的算法出问题往往很难只看最终输出定位，把中间每一步的结果（边缘图、二值图、轮廓叠加图）都保存下来对比，能极大提升调试效率——这点其实和深度学习里"可视化中间层特征图"是一个道理。

6. **注意 OpenCV 版本兼容性差异**。比如 `cv2.findContours` 在 OpenCV 3.x 返回三个值，4.x 之后返回两个值；`SIFT`/`SURF` 在不同版本里是否需要 `opencv-contrib-python` 也不一样，跨版本迁移代码时这些细节容易踩坑。

7. **能用整数运算就别用浮点**，尤其是嵌入式部署场景，`cv2.CV_8U` 相比 `cv2.CV_32F` 能省下不少内存带宽和计算开销。

   

## 19 传统 CV 应用方向总结（工程视角速记）

如果把传统 CV 当作一套“可复用的工程方法论”，我更建议按 **应用方向** 来建立你的心智地图——因为方向决定了你需要的约束、评价指标与 pipeline 形态。

- **工业质检 / 精密测量**：核心诉求是 *确定性 + 可追溯 + 几何精度*。典型套路是“预处理稳住成像 → 边缘/轮廓结构化 → 几何拟合/亚像素 → 规则过滤与统计”。

- **定位配准 / 拼接 / 视觉对齐**：核心诉求是 *找到可靠对应关系*。典型套路是“特征点/描述子 → 匹配 → RANSAC 几何一致性验证 → 单应/位姿解算 → 融合”。

- **文档扫描 / OCR / 条码二维码**：核心诉求是 *规则结构提取*。典型套路是“边缘/轮廓/直线 → 透视矫正 → 二值化（自适应/Sauvola/三角阈值）→ 形态学清理 → 交给识别引擎”。

- **视频前景提取 / 运动分析 / 目标跟踪**：核心诉求是 *时序一致性*。典型套路是“背景建模/帧差 → 形态学清理 → 候选目标 → 卡尔曼预测 + 数据关联”。

- **机器人导航与 SLAM**：核心诉求是 *实时性 + 几何约束*。典型套路是“特征/光流 → 位姿估计（PnP/双目）→ 鲁棒优化”。

工程落地时，一个很稳的起手式是：先用传统 CV 把问题做出一个**可解释、可量化的 baseline**（哪怕精度一般），再决定是否上深度学习；这样你能更清楚地知道深度模型到底在解决什么“剩余难题”，而不是盲目堆模型。

写到这里，回过头看一眼整篇文章的脉络：从 core 模块的基础操作，到预处理的地基，到特征提取的"内功"，到边缘/轮廓/分割解决"这是什么形状"，到检测/匹配/跟踪解决"这是什么、在哪、怎么动"，再到三维视觉解决"这在空间中的什么位置"，再到 Video/DNN/contrib/GUI 这些偏工程落地的能力模块——传统计算机视觉其实构建了一套相当完整、自洽的方法论体系，而且这套体系里的每一个模块，几乎都能在 OpenCV 里找到成熟、高效的实现。

深度学习确实在语义理解、复杂场景泛化能力上带来了革命性的突破，这点毋庸置疑。但也正如第十六章那一堆流水线案例所展示的——**真正落地的视觉系统，很少是"纯深度学习"或"纯传统方法"的极端形态，更多的是两者优势互补的混合体**。传统 CV 提供的可解释性、低成本、高精度几何计算能力，在很多场景下依然是深度学习模型难以替代的"最后一公里"。

所以啊，与其把传统 CV 当作要被淘汰的"过去式"，不如把它看作每个视觉工程师都应该扎实掌握的基本功——它教会你的，不仅仅是几个 API 怎么调用，更是一整套"如何用数学和几何的语言去描述、拆解视觉问题"的思维方式。而这种思维方式，即便是在设计和调试深度学习系统时，同样受用。
